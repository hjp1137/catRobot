# 任务23 远程MySQL真实持久化与内容发布小游戏生效闭环计划

## 1. 当前状态

- 任务22已建立 NestJS、Prisma、管理端、发布快照和游戏读取链路。
- 2026-07-13 已实连远程 MySQL 8.0.33 的 `cat_robot`，已发布到 `R000003`。
- 最近修复过后台登录表单、JWT 缺失和 Prisma 连接池参数。

## 2. 数据库安全措施

- 禁止执行 `migrate reset`、`db push --force-reset`、DROP、TRUNCATE 或无条件 DELETE。
- 只运行 `prisma validate/generate/migrate status/migrate deploy` 和最小必要读写。
- 任何临时内容修改必须记录原值，并通过历史版本恢复或反向修改恢复。
- 不输出完整 `DATABASE_URL`、密码或服务器敏感信息。

## 3. 连接与迁移验证

- 使用 `server/.env` 执行 MySQL 版本、数据库、用户脱敏、字符集、排序规则、时区和 `content_%` 表检查。
- 执行 `npx prisma validate`、`generate`、`migrate status`；如有待执行 migration，先审查 SQL 再 deploy。

## 4. Seed 与 Art 同步

- 运行 `npm run content:db:seed` 两次验证幂等，不覆盖已有配置。
- 运行 `npm run content:art:sync` 两次验证幂等，不删除人工维护数据。
- 查询敌人、背景、主角、关卡、美术资源数量。

## 5. 后台与持久化验证

- 优先通过真实 NestJS API 与管理端同源接口验证登录、profile 和总览。
- 对 `enemy_scrap_mouse_01` 记录原始 `maxHp`、`moveSpeed`、`idleArtKey`、`rowVersion`、`updatedAt`。
- 临时修改血量，确认 rowVersion、change log、draft revision、draft dirty 和重启后保留。
- 验证乐观锁 409 与引用删除保护。

## 6. 校验、发布、快照

- 执行完整校验，错误为 0 后发布。
- 记录发布前后 release、checksum、system state 和 snapshot 表。
- 确认 `content-store/published/content.snapshot.json` 与 `src/content/generated/contentSnapshot.ts` 写入一致。
- 校验快照不包含管理员信息、连接串、软删除内容或后台元字段。

## 7. 游戏读取与生效验证

- 运行 `check:content`、`typecheck`、`build`、`npm test`。
- 检查 `globalThis.__MEOW_CONTENT_TEST_STATE__` 来源为 `mysql-published-snapshot`，release 与 checksum 匹配。
- 用发布快照验证敌人血量、Art Key 或关卡绑定、背景主题来自数据库发布内容。

## 8. 历史恢复与失败保护

- 用历史版本恢复为草稿，校验后重新发布，最终回到任务前正常配置。
- 用可控校验错误或单元测试验证发布失败不覆盖旧 JSON/TS 快照，不更新 current release。

## 9. 自动化与手动验证

- 根项目：`typecheck`、`build`、`check:art`、`check:content`、`npm test`。
- 后端：`typecheck`、`build`、`test`、`test:e2e`。
- 管理端：`typecheck`、`build`、`test`。
- 成果说明提供后台 GUI 和微信开发者工具手动验证步骤；不强制 GUI 自动化微信开发者工具。

## 10. 不处理范围

- 不做图片上传、裁剪、Manifest 自动登记、热更新、Redis、消息队列、微服务或整体 UI 重做。
- 不修改战斗或渲染代码来伪造配置变化。
