# 任务11：装备锁定、筛选与背包分页优化计划

## 一、方案目标
通过新增装备锁定（防止误分解）、背包筛选（按槽位、品质）、列表分页（每页6件）以及Toast操作反馈，提升装备舱界面管理的安全性与清晰度。

## 二、方案细节

### 1. 数据模型与存档迁移
- 扩展 `EquipmentInstance` 结构，新增 `locked?: boolean` 可选属性。
- 更新 `SaveManager.ts` 中的 `migrateEquipmentInventory`，为旧装备补足 `locked: false`，并过滤无效属性。
- 保证锁定状态能够持久化至微信 storage (即读写一致)。

### 2. 装备锁定/解锁与分解校验
- 新增 `toggleEquipmentLock` 与 `isEquipmentLocked` 业务逻辑方法，放置在 `src/data/EquipmentEnhance.ts` 中。
- 分解时（`tryDisassembleEquipment`），优先校验 `item.locked === true`。若是则拒绝分解，并返回 `reason: 'locked'` 错误。
- 史诗装备掉落默认锁定策略：在 `EquipmentHelper.ts` 的 `generateEquipmentInstance` 方法中，自动对史诗级（epic）装备设置 `locked: true`。

### 3. 背包筛选与分页逻辑
- 装备面板 UI 引入 `slotFilter`（'all' \| 'weapon' \| 'armor' \| 'core'）与 `rarityFilter`（'all' \| 'common' \| 'rare' \| 'epic'）过滤器。
- 引入分页组件，每页显示 6 件（`pageSize = 6`）。包含上一页、下一页、第 `page / totalPage` 页。
- 过滤后自动重置页码为 0。
- 若分解导致当前页空，自动向前翻页。

### 4. Canvas UI 优化与交互升级
- **详情弹窗**：高宽微调，新增「锁定」/「解锁」按钮区，若已锁定则分解按钮显示置灰或拒绝。
- **列表锁图标**：锁定装备前缀显示 🔒。
- **Toast 操作反馈**：在面板渲染一个顶部或底部的漂浮通知条（由 `toastMsg` / `toastTime` 控制），穿戴、卸下、强化、分解、锁定、解锁成功时均触发，1.5 秒后淡出。

## 三、验证计划
- 编写全面的自动化单测 `test/EquipmentEnhance.test.ts` 以测试锁定/解锁状态、迁移默认值、史诗锁定、筛选过滤、组合筛选和分页防越界。
- 扩展集成冒烟测试 `test/smoke.runtime.test.ts` 中的装备流程，覆盖：筛选武器 → 筛选史诗 → 翻页 → 详情 → 锁定 → 尝试分解失败 → 解锁 → 分解成功。
