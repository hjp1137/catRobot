# 任务15.1：自由探索 HUD 目标显示与计数封顶补调计划

## 本任务目标
- 修正自由探索 HUD 中目标进度超额显示、当前存活敌人与累计击败目标混淆的问题。
- 保持内部真实累计值、目标完成判定和固定屏 `1-1` 战斗不受影响。
- 补充完成后停刷探针字段，并轻量提升资源点、宝箱提示。

## 当前问题
- HUD 可能展示 `目标 21/12 敌`、`2/1 箱` 等超额进度。
- 顶部同时显示 `敌人 9/12` 与目标击败数，用户难以区分存活数和累计击败数。
- 目标文本与血条、金币、模式信息集中在顶部，观感拥挤。
- 资源点和宝箱提示偏弱，完成后停刷缺少明确探针字段。

## HUD 调整方案
- 探索 HUD 使用“训练场 / 自由探索 / 存活 x / 金币 +x / 目标：...”分层显示。
- 目标文本改为 `目标：击败 x/y｜资源 x/y｜宝箱 x/y`，完成后显示 `训练完成`。
- 固定屏战斗沿用原 HUD 字段，不新增探索目标展示。

## 计数封顶方案
- 新增目标显示快照或格式化逻辑，对击败、资源、宝箱显示值执行 `min(raw, required)`。
- 保留 `enemyKills`、`resourcesCollected`、`chestsOpened` 原始累计值用于完成判定和调试。
- 探针同时输出 raw/display/required 字段，便于自动化验证。

## 完成后刷新控制验证方案
- 保持 `ExploreEnemySystem` 以 `objective.completed` 跳过主动补怪。
- 探针新增 `spawnPaused`，完成时应为 `true`。
- 测试覆盖完成后多次更新不再增加存活敌人。

## 测试计划
- 扩展 `test/exploreTask15.test.ts` 覆盖目标显示封顶、文案区分、完成提示、停刷字段、资源和宝箱显示状态。
- 保留并运行任务指定测试、`npm run typecheck`、`npm run build`、`npm test`。

## 风险点
- `BattleUI` 为固定屏与探索共用，布局调整需保持探索字段可选。
- 资源点和宝箱仅做程序化轻量提示，不引入正式素材和复杂交互。
