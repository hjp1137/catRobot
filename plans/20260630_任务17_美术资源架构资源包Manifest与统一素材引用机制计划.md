# 美术资源架构、资源包 Manifest 与统一素材引用机制计划

## 1. 任务目标
建立一套轻量、可扩展、可替换的美术资源管理架构，避免代码中硬编码图片路径，使得玩家、敌人、地图、UI、技能、特效、掉落物等美术素材均可通过统一 Key 及 Manifest 引用，为未来资源包平滑替换奠定规范。

## 2. 核心架构设计

### A. 资源 Manifest 与包管理 (Manifest & Pack)
- **Manifest 文件**：在 `src/assets/ArtManifest.ts` 中声明 `ART_MANIFEST` 和 `ART_PACKS`。
- **资源包 (Packs)**：Manifest 支持 `ART_PACKS` 概念，区分资源包如 `base`（基础资源包，启用状态为 true）、`prototype`（程序化/占位资源包，启用状态为 true）及 `training_ground_v1`（未启用的测试资源包）。
- **字段规范**：
  - `path`: 资源的物理存在路径。
  - `type`: `sprite` | `icon` | `background` | `placeholder` 等。
  - `pack`: 资源所属的 package。
  - `fallback`: 当资源加载失败或缺失时回退的 placeholder 资源 Key。
  - `virtual`: boolean。如果是 true 则代表是虚构/程序化自绘资源，不参与物理文件存在性检查。
  - `width` / `height`: 可选的尺寸配置信息。

### B. 统一资源 Key (ArtResourceKey)
- **Key 文件**：在 `src/assets/ArtResourceKeys.ts` 中使用 TypeScript 的 `type ArtResourceKey` 严格枚举目前所有图片资源的字符串标识符。
- **命名规范**：遵循 `类别.对象.细分`（如 `player.mechaCat.idle`，`enemy.scrapMouse.normal`，`ui.skill.shield`，`drop.coin`）。

### C. 统一资源解析器 (ArtResourceResolver)
- **Resolver 文件**：在 `src/assets/ArtResourceResolver.ts` 中提供：
  - `getArtResource(key: ArtResourceKey): ArtResourceEntry` (获取完整配置)
  - `getArtPath(key: ArtResourceKey): string` (获取解析后的物理图片路径，若不存在则回退至 fallback，若 fallback 也不存在则给出警告报错)
  - `getArtFallback(key: ArtResourceKey): string` (获取回退路径)

### D. 现有加载器与渲染器引用改造
- **加载器重构**：将 `src/core/ResourceManager.ts` 中写死在 `IMAGE_RESOURCES` 的各种图片路径，改为使用 `ArtResourceKey` 所对应的映射路径，自动从 `ART_MANIFEST` 中提取需要加载的所有物理图片列表，消灭所有的路径硬编码。
- **渲染器与UI适配**：将 `BattleUI.ts`、`MechaRenderer.ts` 等直接使用硬编码字符串资源 Key 的地方（例如 `status_poison`、`ui_tutorial_arrow`），统一通过 `ArtResourceResolver` 或对齐到最新的 `ArtResourceKey` 来取得并加载，保留原有逻辑不倒退。

### E. 资源缺失检测检测脚本与文档
- **检测工具**：在 `scripts/check-art-assets.cjs` 建立统一缺失检测工具。可检测 Manifest 中所有非 `virtual` 物理图片是否存在、fallback 的 Key 是否存在、是否存在重复 Key、是否存在路径配置错误，并在检测失败时输出详细日志报告并抛出 `exit 1` 错误退出。
- **检测命令**：在 `package.json` 中配置 `npm run check:art` 指令。
- **说明文档**：编写 `docs/美术资源包与素材替换说明.md`。

## 4. 风险点与应对
- **资源缺失报错阻断构建**：由于部分新资源可能还没有物理文件图片（例如我们只是定义了 Key 和 Manifest 用作占位符），如果直接检测会阻断构建。
  - **应对**：在 Manifest 中引入 `virtual: true` 或正确设置 `fallback` 并准备好基础占位物理文件（如 `placeholder`），保证脚本在检测到 virtual 或者是已正确降级的资源时正常绿灯通过，仅在致命资源彻底丢失且无法 fallback 时报错。
