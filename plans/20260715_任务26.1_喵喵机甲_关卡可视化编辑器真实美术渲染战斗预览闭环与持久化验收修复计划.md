# 任务26.1 关卡可视化编辑器验收修复计划

## 1. 边界
- 增量修复任务26现有 Prisma 模型、migration、事务保存、StageDirector、快照和后台路由，不推倒重写。
- 保持 `R000005`、`R000006`、`R000007` 不变，不发布新 Release，不开始任务27。
- 管理后台模拟只作为 Web 编排验收，不冒充微信小游戏运行证据。

## 2. 修改前实际检查
1. `/content/stages/:stageId/editor` 由单个 89 行 `StageOrchestrationEditor.vue` 组成，只有工具栏、两侧栏、画布和波次折叠框。
2. 画布用普通 `div/button` 显示图层名称和出生点文字，没有真实图片、拖动与选中属性表单。
3. 编排 API 的图层只返回 `artKey`；统一资源摘要由 `/content/resources/:artKey` 返回状态、来源和 `thumbnailUrl`。
4. 没有关卡专用缩略图接口；现有资源体系可通过图层 Art Key、内容快照中的英雄/敌人 visual Art Key 解析真实图片。
5. 当前没有出生点拖动事件，只有点击写入 `selected`。
6. 属性栏仅用 `a-descriptions` 展示选中 ID、预览状态和来源，没有双向字段绑定。
7. 波次列表是只读 `a-table`，没有波次或条目编辑表单、排序、复制和删除操作。
8. 后台预览仅直接切换 `READY/WAVE_RUNNING/PAUSED` 字符串，没有计时、生成、清场、失败或多波推进。
9. 游戏端 `StageDirector` 已有完整独立状态机；后台未共享它，只是静态按钮模拟。本次后台采用独立、可测试的内存模拟器。
10. 当前只有 MySQL 草稿编排 GET/PUT；“已发布”单选按钮没有调用正式快照 API，也没有隔离数据。
11. `R000007` 内容快照未声明 `stageOrchestrationReleaseId/checksum`，正式预览应返回旧逻辑回退，不可展示草稿三波。
12. 保存接口核对 `rowVersion`，事务成功后自增；冲突当前返回通用 `CONTENT_CONFLICT`，前端没有可恢复提示。
13. 当前没有 dirty 状态、应用内离开确认、`beforeunload`、撤销或重做。
14. 工程未安装 Playwright；此前只做过 Chrome headless 单页截图。登录走现有 JWT，3100/5602 在检查时均未启动。
15. 远程 MySQL 为 `124.221.17.54:3306/cat_robot`；5 个 migration 已应用，schema 为最新。

## 3. 根因与修复路径
- 根因：任务26后台是结构性占位实现，测试仅断言源码文本，未建立可执行交互模型和真实资源数据流。
- 后端：补只读正式编排摘要，规范 409/引用错误结构，严格校验图层资源，保留现有事务和表结构。
- 前端：拆出可测试的编辑历史、坐标与预览模拟器；重构页面为对象栏、真实画布、属性栏和可编辑波次区。
- 资源：始终调用统一资源摘要/缩略图 API；英雄、敌人、背景沿现有内容与资源关系解析，Missing/Invalid 明示。
- 保护：加入 dirty、导航/刷新提示、撤销重做、409保留本地修改与重新加载入口。

## 4. TDD与实施顺序
1. 管理端先补资源解析、坐标、历史记录、预览状态机、发布隔离、409与离开提示红灯测试。
2. 后端先补正式预览回退、图层资源校验、冲突和引用详情红灯测试。
3. 以最小实现使专项测试转绿，再接入页面与样式。
4. 用真实浏览器完成编辑、保存、刷新、NestJS 重启、三波通关、失败、发布隔离、409与离开提示。
5. 记录 `badResponses/pageErrors/consoleErrors`，保存至少19张真实后台截图与结构化 GUI 报告。
