# 任务31：图库、美术资源与游戏资源职责分层重构计划

**目标：** 在既有 MySQL、Art Key、版本、Release 与快照链路上增量加入图库层，使业务页只绑定 Art Key。

**架构：** 图库保存原图和不可变派生版本；Art Resource Version 可引用图库实体但保留历史 `storage_path`；发布仍从资源版本复制最终文件到 Release。资源查询改为后端分页和分类统计，引用扫描复用现有跨业务引用服务。

**技术：** NestJS、Prisma/MySQL、Sharp、Vue 3、Ant Design Vue、Vitest。

## 文件边界

- `server/prisma/schema.prisma`、migration：图库实体和 Art Resource Version 可选关联与索引。
- `server/src/modules/image-library/*`：上传、分页、处理、引用与归档 API。
- `server/src/modules/art-resources/*`：分页、中文分类、引用摘要、图库选图建版本和真实 Alpha 校验。
- `admin/apps/web-antd/src/views/content/*`：图库页、资源页分页/Tab/引用和路由菜单。
- `admin/apps/web-antd/src/components/ArtResourceSelector/*`：分页选择、只保留绑定/换绑与跳转。
- `server/test/*`、`admin/apps/web-antd/src/**/*.test.ts`：闭环回归。
- `scripts/*`：幂等存量图库回填与统计。

## 约束核对

- 不删除历史 Art Key、版本、Release、快照或资源目录；不以 JSON 取代 MySQL。
- 图片处理只新增图库派生版本，Alpha 以 Sharp 真实像素检测为准。
- 业务资源不新建业务模型，只保留 Art Key 绑定；旧上传入口改为图库/美术资源跳转。
- 发布只读取资源版本的最终文件，不在小游戏运行时访问图库。
