# 任务1：喵喵机甲 微信小游戏 MVP 工程 方案

## 一、技术栈决策（与任务文档的偏差说明）

任务文档原始要求：Cocos Creator 4.x + TypeScript。

**实际采用：原生微信小游戏 + TypeScript + Canvas 2D**。原因：

1. 当前工程已是原生微信小游戏工程（`game.js`/`game.json`/`project.config.json`，appid `wx199a1710156d3471`，libVersion 3.15.2）。
2. 本机无 Cocos 编辑器，无法对 Cocos 工程（.scene/.prefab）做本地闭环验证，违反「禁止让用户充当测试员」「必须本地自验证」原则。
3. 原生小游戏 + Canvas 2D 可在微信开发者工具中直接预览，纯逻辑层可用 Node.js 单测验证。
4. 用户已确认（问答环节）选择「原生微信小游戏 + TypeScript」「直接删除旧 demo」。

## 二、整体架构

### 分层
```
src/
├─ engine/      渲染引擎：Canvas 封装、Input、资源、对象池、事件
├─ core/        全局管理：GameManager（场景/状态机）、SaveManager（存档）、EventManager
├─ data/        配置与玩家数据：PlayerData、StageConfig、MechaConfig、UpgradeConfig
├─ player/      PlayerMecha
├─ enemy/       EnemyMouse、EnemyFactory
├─ battle/      BattleManager（战斗主循环、生成、胜负判定）
└─ ui/          MainUI、BattleUI、ResultUI
```

### 场景状态机（GameManager）
`MENU`（主界面）→ `BATTLE`（战斗）→ `RESULT`（结算）→ 回 `MENU`

### 帧循环
`requestAnimationFrame` → `dt` → `input` → `逻辑 update` → `渲染 render` → `UI draw`

## 三、核心数据模型

### PlayerData（持久化）
```ts
{
  mechaId: 'orange_cat',
  level: 1,
  gold: 0,
  parts: 0,
}
```
派生属性（不存盘，每次根据 level + MechaConfig 计算）：
- maxHp = baseHp + (level-1) * hpGrowth
- attack = baseAtk + (level-1) * atkGrowth
- power = maxHp + attack * 10

### MechaConfig（配置）
```ts
{ id, name, baseHp:100, baseAtk:10, speed:200, hpGrowth:20, atkGrowth:5,
  attackRange:120, attackCooldown:0.8, color:'#ff8c1a' }
```

### StageConfig
```ts
{ id:'1-1', name:'训练场 1-1', enemyCount:4, enemyType:'mouse',
  rewardGold:50, rewardParts:5 }
```

### UpgradeConfig（公式）
```ts
costGold(level) = level * 50
costParts(level) = level * 5
```

## 四、战斗系统

### PlayerMecha
- 输入：键盘 WASD/方向键（debug）+ 触摸摇杆（小游戏原生）
- 屏幕边界夹取
- 自动攻击：每 `attackCooldown` 秒，扫描半径内最近敌人，发射近战伤害（视觉为撞击特效）
- hp 归 0 触发失败

### EnemyMouse
- 每帧朝玩家方向移动（简单追踪，无寻路）
- 接触玩家后，每 `enemyAttackCooldown` 秒造成 `enemyAtk` 伤害
- hp 归 0 → 死亡，从敌人列表移除

### BattleManager
- 按 StageConfig 一次性生成 enemyCount 只机械鼠（简单 MVP，不做波次）
- 主循环 update 全部实体，渲染全部实体
- 全部敌人死亡 → 胜利，结算金币/零件
- 玩家死亡 → 失败

## 五、UI（Canvas 2D 手绘）

### MainUI
- 标题、机甲名、等级、战力、金币、零件
- 按钮：开始战斗 / 升级机甲
- 点击检测：矩形 hit-test

### BattleUI
- 玩家血条（顶部）
- 关卡名、敌人数（顶部）
- 触摸摇杆（左下）+ 移动端可拖动整屏移动

### ResultUI
- 胜利/失败标题、奖励、返回按钮

## 六、存档（SaveManager）

- `wx.setStorageSync('mecha_save', json)` / `wx.getStorageSync`
- 浏览器/Node 测试降级到 `localStorage`
- 存档版本号 `v1`，未来 schema 升级走迁移
- 写时机：升级、结算发奖、战斗开始

## 七、微信小游戏适配

- `tsconfig.json` target ES2015 module CommonJS
- 编译 `src/**/*.ts` → `dist/**/*.js`（保留目录结构）
- `game.js` 改为 require 编译后的 `dist/main.js`
- 触摸输入用 `wx.onTouchMove`，键盘调试输入仅在浏览器/Node 可用时启用
- 设备像素比适配：`wx.getSystemInfoSync()` 取 `windowWidth/windowHeight`

## 八、本地自验证（闭环）

无法启动微信开发者工具，故采用**分层验证**：
1. **TypeScript 编译验证**：`tsc --noEmit` 通过 = 类型与语法无误
2. **Node 单元测试**（纯逻辑层，与渲染解耦）：
   - PlayerData 升级公式、存档读写
   - BattleManager 胜负判定、敌人伤害、奖励结算
   - SaveManager localStorage 降级
   - 触摸/键盘输入对 PlayerMecha 位移的影响
3. 测试用 `node:test` 内置 runner，断言用 `node:assert`
4. 给逻辑层注入一个 `IContext`（提供 Canvas/Storage/Input/Now 的抽象），使其在 Node 下可用 mock 实现
