# 符文等级、随机词条与三合一属性规划

日期：2026-10-18。状态：设计提案，数值为首轮调参起点；本轮没有实现新等级、词条或合成，没有改变游戏配置与存档。

## 1. 总体方案

- 符文成为主要构筑系统：六部位机甲负责基础与套装，符文负责属性取舍、攻击方式与触发联动。
- 首批14个常规符文家族，分7种部件；每个家族1～6级，同名同级也有不同数值、副词条和机制分支。名称保持2～3字。
- 等级与品质合为一条成长轴，不再增加独立星级、强化等级或升阶材料。
- 三枚同等级符文合成一枚高一级符文，100%成功；不要求同名或同部件。主材料决定成品家族与部件，辅助材料只提供升级材料。
- 主属性方向固定；数值和副词条重新随机。3级开始获得一条核心机制，后续升级保留主材料的机制分支，只重新随机其强度。
- 六个机甲部位及左右武器各5孔不变。符文不另做套装件数，先把每个孔位的选择做深。

| 等级 | 品质/边框 | 主词条 | 随机副词条 | 核心机制 | 等级系数S | 合成最低1级等价数量 |

| 2级 | 精良/绿 | 1 | 1 | 0 | 1.50 | 3 |

- “黑铁/青铜/白银/黄金/星辰”仍是机甲套装等阶，不能拿来替代符文等级。符文显示“3级·稀有·烈刃”。

- 用部件轮廓＋家族刻纹区分类型，以边框/等级数字区分等级；不能只靠宝石颜色表达两个含义。
- 6级封顶，首期不新增三枚6级重铸、付费洗练或继续叠级。

## 4. 同名同级如何不同

每枚符文都是独立UID，不按同名同级直接堆叠。模板决定方向，实例保存实际结果：

1. 主词条类型由家族固定，主词条数值随机。
2. 副词条从适用部件池中抽取，不重复，也不与主词条使用相同属性键。
3. 3级初次抽一条家族机制分支；4～6级沿主材料分支升级，其伤害/增益强度仍随机。
4. 抽取在掉落结算或合成提交时只做一次，结果写入存档；重开、切页、重新镶嵌不得重抽。

数值计算：`数值 = 1级基准B × 等级系数S × 品相Q`。Q由1～100等概率整数映射为`0.85 + 0.30 × (roll-1)/99`。
主/副词条分别独立掷骰。百分比显示至0.01个百分点，生命至0.1点，攻击/防御/秒数至0.01；生成时按此精度量化，底层用明确单位的整数存结果。

| 同为3级烈刃 | 实例A | 实例B |
| --- | --- | --- |
| 固定方向的随机主值 | 本手武器伤害＋2.52% | 本手武器伤害＋2.11% |
| 随机副词条 | 本手射速＋0.60% | 本手暴击伤害＋2.00个百分点 |
| 随机机制分支 | 穿透：额外穿过1名敌人 | 散射：周期追加侧向弹 |
| 使用取舍 | 适合直线清场 | 适合近距离覆盖 |

两枚并非只比较总战力；角色流派、武器和已有词条决定哪枚更合适。

### 机制统一规则

- 一轮射击指某只手的一次开火批次，散弹多枚子弹仍算1轮，双手同一时刻各开火仍是两轮。机制作用域由机制定义决定：烈刃/雷鸣只由镶嵌手触发，计数/CD/去重按手独立；其余家族机制均为角色全局，不因旧符文镶在武器上而改成手域。
- 全局机制共享计数/CD，任一手的原始开火可推进射击计数；标明“本轮/下一次射击”的增益只作用触发的那一手该轮，标明持续时间的全局增益在时限内作用双手。
- 实际受伤按生命真实减少计，闪避/零伤不计；触发后清零，内置冷却期间不累计该机制计数，不在冷却结束后一次释放多轮积攒效果。
- 穿透、连锁、追加弹、反击和冲击波不再触发其他符文的命中/暴击/击杀机制，不能连锁套连锁或反击套反击；它们击杀仍正常计任务、掉落和通关。
- 同一机制ID不按符文数量叠加，只取当前作用域中最强一条；其他数值词条仍生效，面板标“同机制已覆盖”。武器机制按左右手分开比较。
- 不同分支可以共存，但新增穿透最多2个目标、连锁最多2个目标、一次原始射击含原武器/局内增强的弹数最多8枚。超限明确显示，不静默假装生效。
- 触发伤害默认不暴击。其“基准单发”是未计目标特化和暴击的普通单发伤害；全局非武器机制取两手中较高值，武器机制取本手。目标特化只结算一次。
- 计数/内置冷却在本局保存状态，暂停冻结，换关清空；不因背包切页重置。治疗不超过最大生命，符文触发治疗合计每10秒最多恢复15%最大生命，不限制地图中继/宝箱原本的治疗。
- 闪避不作用于地形放电或明确不可闪避的首领招式；危险区仍要求走位。未来燃烧/冰冻不进入首批池，避免同期堆太多状态系统。

为实现时可核对去重，建议家族ID与A/B对应：凝神focus、明镜mirror、厚土earth、回春renewal、铁壁bulwark、坚韧resolve、疾行gale、灵巧agility、守御aegis、玄光radiance、锋芒edge、灵光arcane、烈刃fury、雷鸣thunder。
机制ID为对应`family_id_a`/`family_id_b`，28个明确ID，每个ID就是一个去重组；不同分支不是同组。当前旧config_id保留映射，不因采用家族ID删除旧物品。

## 8. 数值作用域与叠加上限

### 作用域

- 六部位数值以角色为作用域；新武器符文的武器伤害/射速/攻击/暴伤只强化本手，双武器可以分别构筑。
- 现有武器符文是全局加成，迁移不能无提示变为本手；旧实例保留原作用域并标注“旧版全局”，新实例按新规则生成。
- 同属性同作用域先加算，再进入原伤害公式，不能把每枚“＋5%”独立乘起来。装备/套装与符文相同属性也按同一加法桶结算。
- 暴击先建立5%基础概率与150%基础暴伤；符文暴击只作用普通武器，喵能炮/触发伤害首期不暴击。
- 当前skillDamageBonus应在玩家界面称“喵能炮伤害”，不承诺强化全部技能；治疗、闪避、精英减伤等必须新增实际消费链路。

| 对精英/首领伤害 | ＋30% | 同一目标只进入一次目标特化乘区 |
| 喵能炮伤害 | ＋60% | 与其他同属性加算 |
| 普攻暴击率/暴伤 | ＋25个百分点 / ＋75个百分点 | 初始无其他来源时最高30%/225% |
| 技能冷却缩减 | 25% | 全局最多50%，沿用现有总上限 |
| 移速 | ＋20% | 与装备/局内加速同桶，地形倍率另算 |
| 防御白值 | ＋8点 | 先白值减算，再计算减伤 |
| 常驻/精英首领额外减伤 | ＋12 / ＋15个百分点 | 条件减伤与常驻合计的等效减伤不超过70%，护盾另算 |
| 护盾延时/护盾减伤 | ＋1.2秒 / ＋15个百分点 | 护盾减伤全局最多85% |
| 闪避/受到治疗提高 | 15% / ＋50% | 闪避仅可闪避攻击；符文触发治疗另受频次上限 |
| 拾取半径 | ＋100% | 不延长任务或宝箱交互距离 |

减伤结算提案：先汇总常驻减伤与本次攻击满足条件的减伤，加算后最多70%；护盾减伤作为独立层最多85%。同一条“同一敌人第二次伤害额外降低”也进入条件减伤桶，不再额外乘一层。
护盾另加共同约束：单次持续最多7.5秒，结束后至少2.5秒才能再次开启，理论覆盖率不超过75%；冷却仍从施放时计算，冷却返还不能突破间隔限制。
现有满技能/套装/冷却组合可能已超过该覆盖率，正式实现前必须重新核算基础配置与实际生存，不得直接把旧档改值后上线。
超出上限的词条在配装预览明确显示“有效值/超出部分”，方便换流派；不得让玩家看到面板增加却没有战斗收益。

固定白值和武器、仅估算符文数值收益：武器伤害＋60%、射速＋35%、暴率从5%到30%、暴伤从150%到225%，普通持续输出比约为`1.6×1.35×1.375÷1.025≈2.90`；打精英/首领再含30%目标特化时约3.77。机制/白值另算，不把该估算当实战保证。

## 9. 三合一与材料保护

1. 选择1枚主材料，再选择2枚同等级辅助材料；三枚UID必须不同、属于玩家、未绑定任何装备且未锁定，1～5级可合成。
2. 辅助材料允许不同部位/家族，避免七类材料互相卡住；成品部位、名称与主属性方向由主材料确定，不随机变成另一种部件。
3. 100%成功且不额外消耗金币、强化石或新材料。输出为等级＋1、全新UID；主/副数值和副属性重新随机。
4. 主材料2级升3级时随机首次机制；主材料已有机制时沿其分支，强度按新等级再随机。保留想玩的分支，不强迫顶级成品重新抽玩法。
5. 正式确认前展示成品等级、固定家族、可出现词条/机制与数值范围，并提示“副词条将重抽”；不能提前展示尚未生成的确切成品属性。
6. 一次提交完成“删除3枚＋新增1枚＋保存”；失败全部恢复，成功后再播合成动画。按钮处理期间不能重复提交，重开不能重复领成品。
7. 新增符文锁定；自动选择仅选未绑定、未锁定辅助材料，主材料由玩家明确指定。好词条不按“较低战力”自动吃掉，不默认连续合成全部。
8. 只按等级检查相同，不把同名同级理解成可堆叠物；合成预览可逐枚查看实际词条。已穿戴或背包装备上绑定的符文都先取下才能作材料。

新制主属性每级最低值高于前级最高值，但副属性/机制强度可能更适合或更不适合原构筑，不能用“合成必定提升角色总战力”作承诺。前期优先填空孔，再合成闲置材料。

## 13. 实例与旧档兼容建议

新实例沿现有UID/config_id扩展：`level`、`primary_affix`、`secondary_affixes`、`mechanism`、`locked`、`generation_version`。每个词条保存稳定ID、明确单位的实际整数值；模板负责允许池，实例负责这次抽到的结果。
不把“任意effect字典”当新随机词条的权威输入。预览/结算从已校验的实例生成数值效果与机制列表，不能依赖描述文字，也不能每次读模板重抽。

### 旧实例原则

1. 保留所有UID、配置身份、孔位绑定、原固定效果与原作用域，不因“common/rare”直接硬映射成新1/3级。
2. 旧主值按新版对应基准表，选“主值上界能容纳它的最低等级”；原主值不改，可能低于该等级新下界的历史值明确标“旧版固定”。该映射是兼容显示，不承诺获得新制同级全部词条。
3. 不自动补抽旧符文的副词条/机制，不把旧档全部随机洗掉。用户选择合成后，成品按新模板生成；主材料缺机制且成品≥3级时首次抽取分支。
4. 旧炮击/护盾分别保留武器/上衣部件；升级用主值基准2%喵能炮伤害/0.15秒护盾持续，机制分别复用灵光/守御池，使用相同机制ID避免叠两份。
   旧炮击合成后的灵光机制仍为角色全局，与戒指灵光共享同一计数/CD/去重组；镶在左/右武器不复制主动喵能炮的触发次数。
5. 旧净化/避火保留原数据，等级兼容基准为5个百分点，原15%映为4级；它们不进入新池，也不作为主材料输出未接入的属性。默认锁定，只能用户确认解锁后手动当辅助材料。未来有真实毒/火伤害时再接入，不将抗性混成闪避或防御。
6. 未识别旧配置只读保留，不参与合成；迁移前导出干跑清单，核对数量、UID、绑定和效果。存档版本按实际结构升级一次，重载/再次迁移不得重抽或重复补物。

旧版主值可能不符合新池区间，校验例外只能由可信旧配置及迁移来源确认，不能让外部导入随便写legacy标记绕过范围检查。
新字段必须校验等级、词条数量/类型、部件允许池、数值范围、机制兼容、UID唯一性与孔位引用；现有只检查UID/config_id的逻辑不足。
合成复用现有snapshot→一次模型修改→一次save→失败restore，不新增交易日志、hash或冻结文件；这保证本地业务回滚，不夸称数据库级或服务器级防作弊。
