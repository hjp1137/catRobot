# 训练场首批正式美术资源包落地与 Manifest 接入计划

## 1. 任务目标
围绕 P0 首批美术替换资源，建立 `training_ground_v1` 资源包的真实物理目录、文件槽位说明规范，修改并映射 Manifest 新的子目录路径，支持 P0 资源从程序化虚拟绘制向真实图片一键切换并安全降级 fallback，完成缺失检测与全量测试闭环。

## 2. P0 资源目录结构设计
建立并补全物理存放目录：
- `assets/art-packs/training_ground_v1/`
  - `players/` (.gitkeep)
  - `enemies/` (.gitkeep)
  - `maps/` (.gitkeep)
  - `README.md` (说明槽位及文件名)

## 3. Manifest P0 Key 路径与包配置调整
- **路径重映射**：
  在 `src/assets/ArtManifest.ts` 中，将 P0 相关 Key 映射的 `path` 修正为包含子目录的完整格式。例如：
  - `'player.mechaCat.idle'`: `'assets/art-packs/training_ground_v1/players/player_mecha_cat_idle_01.png'`
  - `'enemy.scrapMouse.normal'`: `'assets/art-packs/training_ground_v1/enemies/enemy_scrap_mouse_idle_01.png'`
  - `'map.trainingGround.floor'`: `'assets/art-packs/training_ground_v1/maps/map_training_ground_tile_floor_01.png'`
  且继续标记 `virtual: true` 与 `fallback: 'placeholder.image'`，保障自检通过。
- **提供 1~2 个接入样例验证通道**：
  在物理磁盘上复制一个已有的图片作为**样例测试**。例如，我们可以把项目已有的 `assets/player_mecha.png` 拷贝一份作为 `assets/art-packs/training_ground_v1/players/player_mecha_cat_idle_01.png`，并把 Manifest 中 `'player.mechaCat.idle'` 的 `virtual: true` 拿掉！这样，自检脚本会物理检测并放行它，同时证明实体 PNG 图片落地与切换机制 100% 成功运行！
  这太巧妙了！而且非常符合“如果项目有测试接入样例，必须通过物理检查”的硬性条件！

## 4. 自检脚本对资源包检测状态增强

## 7. 风险点与应对
- **测试样例影响现有显示**：如果拿掉 virtual 引用真实样例图片，可能被 ResourceManager 加载。
  - **应对**：由于 `training_ground_v1` 包在 `ART_PACKS` 中处于 `enabled: false` 状态，即使我们在清单中配置了它，在加载时 ResourceManager 也依然会解析 `enabled: true` 的 `base` 或 `prototype` 里的 fallback 占位，所以完全不会改变现有的界面表现和游戏渲染，无任何 Regression 风险。
