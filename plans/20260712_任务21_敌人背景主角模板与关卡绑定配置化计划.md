# 任务21 敌人背景主角模板与关卡绑定配置化计划

## 1. 当前硬编码现状

- 固定屏战斗使用 `src/data/StageConfig.ts` 的 `enemies/waves` 和 `src/data/EnemyConfig.ts` 的敌人数值。
- `BattleManager.spawnWave()` 直接用 `ENEMY_CONFIGS[group.enemyId]` 创建 `EnemyMouse`。
- 自由探索使用 `ExploreContentConfig.TRAINING_GROUND_CONTENT.spawnPoints`，刷新点写死 `enemyType`。
- 背景由 `BattleManager.render()` 按 chapterId 分支选择，探索地图由 `ExploreMapRenderer` 固定绘制训练场。
- 主角和技能按钮通过 `ResourceManager` 的 `player_mecha/skill_*` 旧资源键取图。

## 2. 配置化目标

- 新增 `EnemyTemplate`、`BackgroundTheme`、`HeroVisualTemplate`、`StageDefinition`。
- 新建 `ContentRepository`、`LocalContentRepository`、`ContentRegistry`、`ContentValidator`。
- 固定屏 `1-1` 和自由探索训练场先迁移为新内容系统主数据源。
- 旧 `StageConfig` 和 `EnemyConfig` 保留为章节/历史系统兼容层，并标注 deprecated。

## 3. 数据模型设计

- `EnemyTemplate` 负责敌人基础数值、战斗参数、行为类型和 Art Key。
- `BackgroundTheme` 负责背景 Art Key、平铺模式、网格、区域和边界显示开关。
- `HeroVisualTemplate` 只负责主角与技能表现，不混入主角战斗数值。
- `StageDefinition` 通过模板 ID 绑定主角表现、背景主题、敌人波次或探索刷新组。

## 4. 数据源抽象方案

- `LocalContentRepository` 从 `src/content/data/*.ts` 读取纯数据。
- `ContentRegistry.load()` 只初始化一次，加载后集中提供 ID 查询。
- 运行时代码只通过 `ContentRegistry` 或适配函数取模板，不直接遍历数据文件。

## 5. 固定屏迁移方案

- 为 `stage_battle_1_1` 建立 `StageDefinition`，波次迁移自现有 `STAGE_1_1`。
- 提供 `createLegacyStageFromDefinition()` 将新关卡定义适配为旧 `StageConfig`，保持 `WaveManager` 和进度系统稳定。
- `BattleManager` 启动时解析 active stage definition，敌人创建改走模板数值和 Art Key。
- 背景渲染优先用关卡的 `BackgroundTheme`，章节旧分支只作为 fallback。

## 6. 自由探索迁移方案

- 为 `stage_explore_training_01` 建立探索 StageDefinition，迁移 4 个刷新点。
- `ExploreScene.start()` 从注册表读取探索定义，设置世界尺寸、背景主题、主角模板和刷新组。
- `ExploreEnemySystem` 通过 `enemyTemplateId` 生成敌人，不再读取硬编码 `enemyType`。
- 资源点、宝箱、目标配置保持旧配置，避免玩法回退。

## 7. 兼容层处理方案

- `StageConfig`、`EnemyConfig` 继续服务历史章节、进度、掉落、Boss 技能和旧测试。
- 新增 `LegacyStageConfigAdapter`，仅把新内容定义转换成旧结构供现有系统消费。
- 新关卡不得再新增到旧硬编码波次源。

## 8. 校验方案

- 新增 `npm run check:content`，运行 `scripts/check-content-config.cjs`。
- 校验 ID、name、version、enabled、数值范围、Art Key、模板引用和关卡模式。
- 启用关卡不得引用禁用敌人、背景或主角模板。
- 错误输出文件、对象 ID、字段和原因，并以 exit 1 失败。

## 9. 测试计划

- 新增 `contentRegistry.test.ts` 覆盖仓库加载、注册表查询和缺失模板报错。
- 新增 `contentValidation.test.ts` 覆盖合法配置和禁用模板引用失败。
- 新增 `stageContentBinding.test.ts` 覆盖固定屏波次、自由探索刷新、敌人数值和 Art Key 来自模板。
- 保留并运行 `npm run typecheck`、`npm run build`、`npm run check:art`、`npm run check:content`、`npm test`。

## 10. 风险点

- 旧章节仍依赖 `EnemyConfig.variant` 触发 Boss 技能，任务21只迁移 1-1 和探索训练场。
- `ResourceManager` 当前按旧 resource key 缓存图片，需要新增 Art Key 到已加载图片的轻量解析。
- 微信小游戏运行环境不应引入 Node-only 逻辑，校验脚本放在 `scripts/`，运行时只用 TypeScript 数据。
