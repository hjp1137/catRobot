# 章节地图与动态营地计划

日期：2026-10-17。

## 可观察的成功标准

- 战斗页首先展示章地图，点击已开放章节进入章内关卡地图；地图节点显示当前、已通关、可挑战及锁定状态。
- 当前关卡及名称、星级、目标/奖励、出击入口集中于战斗地图，选择和出击继续使用真实解锁与存档规则。
- 营地移除顶部关卡/下个解锁卡片、关卡奖励预览、开始出击与选择关卡入口，保留建筑解锁及底部导航。
- 营地人物使用已有角色动作沿道路随机漫游，补小机器人、车辆、星舰等动态元素；不穿过主要建筑或挡住建筑按钮。
- 页面切换/战斗/退出后无旧动画节点、输入或资源遗留；角色与环境活动只在营地运行。

## 范围与分工

- 主代理：现有章节/解锁链调查，战斗章地图和节地图实现，主界面集成、美术与整体视觉验证。
- 营地代理：只修改camp_ui.gd及新营地活动脚本，复用角色动画，移除指定卡片并接入动态活动。
- 验证代理：独立维护相关现有UI断言和新增地图/漫游专项，验证真实点击、锁定、出击与状态隔离。
- 美术按实际需要补充，保持原有机甲工业风、现有顶部资源栏与小底部导航。

## 执行步骤

1. 检索现有chapter/stage数据、建筑入口、奖励预览及存档选关逻辑。
2. 复用真实章节/节点与奖励数据，构建章地图和章内路线，限制后续未迁移内容的出击。
3. 营地去除战役卡片，接入按可行走道路移动的角色与小型环境单位。
4. 更新已有界面检查；本地隔离存档运行相关测试及必要回归。
5. 实际GPU捕获章地图、节地图、选关信息、锁定状态和连续营地活动，查看图像与活动证据。
6. 写成果说明，更新使用说明并追加开发日记。

## 边界

- 不更改战斗数值、装备/掉落、已有玩家进度或原TypeScript/后台实现。
- 已有未提交工作保持；未开放章节不得用虚构通关数据伪装为可玩。
- 所有验证使用tmp隔离存档，截图中的构造进度与自然流程分开说明。
- 本轮验证为本机Godot桌面，微信真机与长期平衡不作为已验收项。
