## 2. 编码前实查
- 敌人动作字段：`EnemyVisualConfig` 已有 `icon/idle/move/attack/hit/death ArtKey`，MySQL 存在于 `content_enemy_template.visual_json`。
- 主角动作字段：`HeroVisualConfig` 已有 `icon/idle/move/attack/hit/death ArtKey`，MySQL 存在于 `content_hero_visual.visual_json`。
- 单图链路：业务 JSON Art Key -> `ContentValidationService` -> `SnapshotGeneratorService.collectReferencedArtKeys()` -> Art Manifest Snapshot -> `ArtResourceResolver`。
- Canvas渲染：固定屏由 `BattleManager.render()` 调 `drawBackgroundTheme/drawEnemy/drawMecha`；自由探索由 `ExploreRenderer` 绘制。
- 主循环：`GameManager.tick(dt)` 先 update 后 render，dt 秒级，后台大步已限到 0.1。
- 状态切换：敌人有移动/攻击接触/受击闪光/死亡标志；主角有移动输入、攻击闪光、受击闪光、死亡标志。
- 资源加载：`ResourceManager` 固定预加载 `IMAGE_RESOURCES`，`getImageByArtKey()` 只命中已列入资源，需要补 Art Key 去重懒加载。
- 绘制顺序：背景 -> 攻击范围 -> 敌人 -> 投射物/反馈 -> 主角 -> HUD。
- 后台公共组件：`ArtResourceField/Thumb/Selector` 已统一处理缩略图、加载失败和 Missing，不重复建设。
- 发布快照：内容快照和 Art Manifest Snapshot 已由 `SnapshotGeneratorService` 生成并写入 JSON/TS。
- 历史恢复：`ReleasesService.restore()` 仅恢复为草稿，重新发布才生效。
- Prisma状态：`content:db:status` 显示远程 MySQL `cat_robot` 当前 3 个 migration，schema up to date。

## 3. 数据模型
- 新增 `content_animation_clip`、`content_animation_frame`。
- 动作片段独立存储，敌人/主角 `visual_json.animationClipKeys` 保存 Clip Key 引用。
- 保持旧 Art Key 字段有效，解析规则为 Clip 优先、旧静态 Art Key 次之、既有 fallback 最后。

## 4. 后端与发布
- 新增 Animation API：列表、详情、创建、更新、删除保护、引用查询。
- 发布校验补 Clip Key 唯一、帧顺序、帧 Art Key、Missing/Invalid、帧时长、引用存在。
- 生成 `content-store/published/animation-manifest.snapshot.json` 与 `src/assets/generated/animationManifestSnapshot.ts`。
- Art Manifest 收集动作帧 Art Key，资源引用查询包含动画帧。

## 5. 游戏端
- 新增 `FrameSequencePlayer`，覆盖循环、单次、hold-last、暂停、恢复、重置、大时间步和空帧。
- 新增 Animation Manifest 读取与 Clip 解析。
- 敌人与主角按真实状态选择 `idle/move/attack/hit/death`，相同状态不重启，状态变化从首帧开始。
- `ResourceManager` 增加按 Art Key 缓存加载，避免同一帧重复创建图片。

## 6. 管理端
- 新增“动作编排”入口，提供片段列表、帧编辑、资源选择、实时预览、排序、复制、删除和状态筛选。
- 敌人和主角动作字段共用同一 Clip 绑定组件，明确“静态图片/动作片段”模式。
- 关卡配置新增场景预览，展示背景、地板、主角、主要敌人、层级和动作播放。
