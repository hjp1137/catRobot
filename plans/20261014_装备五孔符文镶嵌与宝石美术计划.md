# 装备五孔符文镶嵌与宝石美术计划

日期：2026-10-14。

## 可观察成功标准

- 符文使用独立透明宝石美术及发光纹样，不再复用武器/护盾图标。
- 每件实际装备实例（9个甲件槽与左右手武器）均有5个符文孔，符文绑定装备UID与孔位。
- 分头盔、上衣、裤子、鞋子、护甲、戒指、项链、武器8类；左右护甲/戒指/武器共用对应类型。
- 只允许匹配部件镶嵌；单个符文实例只能镶嵌一处，支持取下及明确替换。
- 仅穿戴中的装备所镶嵌符文生效；换装不自动搬移，分解时符文返还背包。
- 机甲槽位/装备详情显示5孔与占用；符文详情标明适用部位、所在装备及是否生效，并提供实际镶嵌流程。
- 原全局两枚符文迁移至兼容装备孔；不能自动放置的保留背包，不丢实例或重复生效。
- 保留原三星符文奖励；正式关卡胜利新增20%独立符文掉落，八类均可获得，失败/撤离/训练不发。
- 新存档schema3兼容schema1/2与微信JSON；镶嵌与保存失败采用原子回滚。
- 通过核心行为、迁移/异常、真实UI操作和隔离存档GPU截图。

## 实施分工与边界

1. 核心代理：pilot_state/pilot_equipment/pilot_legacy与必要镶嵌逻辑，完成绑定、属性、校验、掉落和迁移。
2. 美术内容代理：新增rune_catalog.json、ContentDB合并、8类宝石图集/rune_art读取和来源记录。
3. 验证代理：更新旧全局符文断言，新增镶嵌行为回归与真实截图工具。
4. 主代理：符文镶嵌界面、装备5孔、背包/明细接入与最终集成验证；不改已确认大框架。

## 公共数据与接口

- rune_catalog包含socket_count=5、drop_probability=.20、type_names、slot_types、legacy_types、runes和drop_ids。
- Pilot.rune_sockets为装备UID到5元素符文UID数组的映射；空孔使用空字符串。
- Pilot.socket_rune(rune_uid,equipment_uid,index)、unsocket_rune(equipment_uid,index)执行原子操作。
- item_preview提供socket_count/rune_sockets；rune_preview提供part_type/part_name、bound_equipment_uid、socket_index及active。
- equipped_runes仅作为当前生效符文的兼容读取入口，不再保存为独立全局装配源。
- 样式和孔位可用性不按等级额外收费或锁定；本轮不加入合成、付费抽取或新的强化系统。
- 所有运行验证使用独立tmp存档；真实玩家存档不作为测试材料，不提交/推送/发布。
