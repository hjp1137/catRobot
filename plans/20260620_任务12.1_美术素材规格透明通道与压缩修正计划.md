# 任务12.1 美术素材规格、透明通道与压缩修正计划

## 1. 目标与背景
任务12已通过全部 290 项集成和单元测试，但美术资产规格（尺寸、透明通道、文件体积）不符合验收标准，需要进行修正。

## 2. 详细执行步骤

### 2.1 美术素材规格调整与透明通道修复
1. 编写 Python 转换脚本 `assets/process_images.py`：
   - 使用 PIL 库加载 `assets/` 目录下的 10 张 PNG 图像。
   - 限制/裁剪并缩放至要求尺寸：
     - `main_bg.png` -> 800×1200
     - `player_mecha.png` -> 128×128
     - `enemy_rat.png` -> 64×64
     - 其他图标（coin, part, stone, equip_icon, rune_icon, skill_cannon, skill_shield） -> 64×64
   - 修复透明通道：
     - 将原为 Format24bppRgb 的图片转换为 RGBA（`main_bg.png` 保持为 RGBA 或 RGB 即可，其他角色与图标必须是带有真实透明通道的 RGBA）。
     - 通过识别底色（如纯白、纯黑或极暗极亮背景）在缩放后将底色抠除（即 Alpha 设置为 0）。为保证透明边缘效果，可采用色差容差（Color Distance Threshold）或直接将满足特定亮度/色差的区域做透明化处理。
     - 确保透明度通道在 PNG 中保存为颜色类型 6（RGBA），并且真实的透明像素存在。
   - 压缩优化体积：
     - 使用 PIL 的优化选项进行保存，并限制存储质量。
     - 首批 10 张素材总大小限制在 2MB 以内；
     - `coin`, `part`, `stone`, `equip_icon`, `rune_icon`, `skill_cannon`, `skill_shield` 单个 <= 100KB；
     - `enemy_rat` 单个 <= 100KB；
     - `player_mecha` 单个 <= 250KB；
     - `main_bg` <= 700KB。

### 2.2 资产清单编写
1. 新建 `assets/ASSET_MANIFEST.md`。
2. 逐项登记 10 个资源的细节：资源键、文件名、用途、像素尺寸、PNG颜色类型、透明要求、实际字节数、来源/生成方式、生成日期、许可状态（标注为“内部原型可替换素材”）、替换步骤和压缩标准。

### 2.3 新增真实资产校验测试
1. 新建 `test/assets.test.ts`：
   - 验证这 10 个图片文件的物理路径确实存在。
   - 验证文件大小及总大小是否在限制范围内。
   - 读取 PNG 的 IHDR 块，解析其实际像素宽高。
   - 解析 PNG 的颜色类型（Color Type）：角色和图标必须是颜色类型 6（RGBA），表示有透明通道。
2. 将 `test/assets.test.ts` 加入 `package.json` 中的 `test` 运行命令。

### 2.4 测试与自验证
1. 运行 `npm run typecheck`。
2. 运行 `npm run build`。
3. 运行 `npm test`，确保总计测试通过（290+ 项，包含新增的真实资产校验测试）。
4. 验证在有真实透明素材的情况下，模拟器的正常交互及渲染不崩溃。
