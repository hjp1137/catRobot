# 任务15：装备套装、第三章装备与道具美术计划

## 1. 目标与边界
- 在现有装备、符文、强化、锁定、分页和掉落架构上增量实现，不重写既有系统，不提前实施任务16。
- 新素材按内部原型可替换素材管理。
- 目标是实现三件第三章熔岩装备及其套装属性（熔岩套装），新增火焰抗性符文并接入掉落，完善对应UI和美术渲染。

## 2. 详细方案

### 2.1 配置方案 (Configuration)
- 装备配置已经在 `src/data/EquipmentConfig.ts` 中就绪，包含 `lava_cannon`（武器）、`lava_armor`（装甲）、`lava_core`（核心），且均关联 `setId: 'lava_suit'`。
- 套装配置在 `EQUIPMENT_SETS` 中定义：
  - 2件套效果：`fireResist: 0.15, attack: 5`
  - 3件套效果：`skillDamageBonus: 0.10, cooldownReduction: 0.05`
  - 2件套战力：30；3件套战力：50。

### 2.2 UI与美术资源方案 (UI & Assets)
- 新增资源键注册到 `src/core/ResourceManager.ts` 中：
  - `equip_lava_cannon`: `assets/equip_lava_cannon.png`
  - `equip_lava_armor`: `assets/equip_lava_armor.png`
  - `equip_lava_core`: `assets/equip_lava_core.png`
  - `rune_fire_guard`: `assets/rune_fire_guard.png`
  - `ui_set_icon`: `assets/ui_set_icon.png`
- 并在 UI 渲染（如装备详情和列表）中：
  - 装备图标展示对应熔岩装备素材；如果是熔岩套装装备，在详情和列表中绘制套装标识（`ui_set_icon`）及文字。
  - 显示套装名称、当前件数（2/3）、各阶段效果（2件套、3件套效果）以及激活状态（未激活灰色，已激活高亮）。
  - 保留 Canvas 程序化兜底渲染，当图片加载失败时用 Canvas 图形代替绘制。

### 2.3 兼容与迁移方案 (Compatibility & Migration)
- 旧存档可能不包含套装数据或旧版符文，我们在读取存档时自动从已穿戴的装备中实时计算套装效果与战力，不将其写入存档冗余字段。
- 支持穿戴、替换、强化、锁定、解锁和分解等，穿戴或锁定中依然禁止分解。

### 2.4 测试方案 (Testing)
- 新增并注册 `test/EquipmentSet.test.ts` 专项单元测试，覆盖 0/1/2/3 件切换、属性计算、战力叠加、上限保护、强化、锁定分解、掉落、旧档迁移和无效配置。
- 扩展微信运行时模拟器冒烟测试，覆盖第三章装备、火抗符文获取与穿戴、UI绘制、加载失败兜底等。

### 2.5 补充测试与迁移方案 (Supplementary Plans)
- **存档迁移清理计划**：在 `SaveManager.ts` 中增强对脏存档的清理机制：
  1. 验证已穿戴和已装备的符文 `configId` 是否合法，剔除不存在或拼写错误的符文 ID。
  2. 验证已穿戴装备的 UID 是否有效，避免装备已被删除但在槽位中依然保留穿戴引用的“悬挂引用”缺陷。
  3. 增加对已穿戴槽位和符文槽最大数量的保护判定，清理超量装备与重复符文。
- **防止测试污染的机制**：对修改全局配置（如 `EQUIPMENT_CONFIGS` 等静态记录）的专项测试用例，增加 `try ... finally` 备份与还原保护，避免后行测试受到污染从而发生雪崩式失败。
- **全方位模拟器集成断言**：
  1. **装备依次穿戴断言**：在集成测试中动态依次穿戴 2 件和 3 件熔岩套装装备，断言不同阶段的激活状态、战力表现及火抗等基础加成数值的递进。
  2. **存档重启恢复断言**：将角色装备和符文存档写盘后，销毁当前引擎上下文并重新读取，断言所有三件装备、火抗符文、穿戴状态、当前战力以及所有关联套装加成均完美恢复。
  3. **Canvas 绘制路径证明**：
     - **成功路径**：通过劫持 canvas `drawImage`，实际断言 `equip_lava_cannon`、`equip_lava_armor`、`equip_lava_core`、`rune_fire_guard` 和 `ui_set_icon` 均有实际的图片绘制（分别覆盖列表页、详情面板和 ResultUI 掉落结算页）。
     - **失败路径**：通过重置加载状态并使资源加载失败，断言在三处渲染逻辑中绝不调用这些新资源图片，而是由程序化兜底逻辑（`fillRect` / `strokeRect` / `arc` / `fill` / `stroke`）代替绘制。
