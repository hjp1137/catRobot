# 任务31：第一阶段全链路集成、正式 Release 发布与总验收计划

## 目标与边界

以远程 MySQL `cat_robot` 的草稿为唯一后台数据源，完成完整校验、原子 Release、快照和小游戏构建验证；不新增第二阶段功能，不覆盖历史 Release，不伪造微信开发者工具验收。

## 已继承基线

- 任务21—30的计划与成果说明已纳入审计；任务30明确未发布新版本。
- 现有正式端为 `R000007`，其教程接口处于 `LEGACY_FALLBACK`，不能作为本任务的最终正式快照。
- 正式 Campaign 节点必须为 `free-map`；固定屏仅保留开发调试用途。

## 执行顺序

1. 审计工作区、环境、Migration、远程数据、已有 Release/快照及测试残留；记录安全基线。
2. 以现有发布服务与校验器为唯一发布路径，补齐任务31自动化回归：发布原子性、版本/校验和一致性、终态互斥与历史恢复。
3. 运行根项目、后端、管理端、内容/资源/动画/Stage/Campaign/Tutorial 门禁；对每个失败先定位根因并最小修复。
4. 创建不含凭据的发布前备份清单，在远程草稿上运行完整校验；仅在零错误且无阻断告警时触发系统生成的下一 Release。
5. 核对数据库发布记录、内容/美术/动画/Stage/Progression/Campaign/Tutorial 快照、版本化资源目录及 checksum，并保留旧版本。
6. 清理小游戏构建缓存并使用新 Release 构建；核验正式快照探针与无调试入口。
7. 进行可自动化的后台 GUI 复核；微信开发者工具部分仅提供人工步骤、探针和截图清单，明确记录用户已有任务30人工结果。
8. 验证历史 Release 恢复为草稿不改变当前正式版；安全构造并恢复一次校验失败保护证据，收集行版本冲突证据。
9. 写入成果说明、第一阶段验收报告和开发日记；按证据列出未验证项与 P0/P1/P2，不自行判定 PASS。

## 发布安全阈值

- 只通过既有业务发布 API/服务发布，禁止 SQL 直改正式版本。
- 发布前保留当前 Release、草稿和快照清单；任何校验、快照、资源复制或 checksum 失败均停止，不切换 Current Release。
- 不输出数据库 URL、密码、Token 或私钥；日志仅记录脱敏状态和版本/校验和。
