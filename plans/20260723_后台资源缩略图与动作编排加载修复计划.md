# 后台资源缩略图与动作编排加载修复计划

## 现场结论

- `contentApi.resources()` 已归一化为数组；`ArtResourceSelector` 仍读取 `result.items`，导致资源列表变成 `undefined`，触发 `filter/map` 异常并误报帧资源无效。
- 缩略图接口仅依据原图版本判断可展示，未检查缩略图文件存在性；文件缺失交由 Express `sendFile` 处理，浏览器得到 500 并等待超时。

## 实施

1. 增加前端回归断言：选择器直接消费资源数组，加载失败保留空列表。
2. 增加后端回归用例：缩略图文件缺失时回退原图，且 MIME 与返回路径一致。
3. 修正选择器的数据形状与并发加载保护。
4. 复用资源列表已解析的版本，避免并行缩略图请求逐张争用远程 MySQL 单连接。
5. 将远程 MySQL Prisma 连接池从单连接调整为保守并发，并复用列表后的资源详情摘要。
6. 为动作预览的缺失资源摘要增加成功、失败和进行中缓存，禁止切帧重试风暴。
7. 修正资源文件解析：缩略图缺失时从原图补建 WebP，原图也缺失时返回明确的非 500 响应；执行前后端与资源校验。
8. 同步连接池示例配置与 README 后台启动、资源预览故障排查说明。

## 验收

- 动作片段编辑器不再出现 `filter/map` 未定义异常，已存在帧不再误报 `Invalid资源`。
- 缺失缩略图不返回 500；首次请求补建轻量 WebP，后续页面直接加载缩略图。
- 类型检查、前后端测试和资源校验通过。
