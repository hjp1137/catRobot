# 任务20 训练场 P0 首版可见美术素材替换与 GUI 效果验证计划

## 任务目标
不再停留在资源包槽位和 Manifest 预留层面，而是至少落地一批能在微信开发者工具中直接看见变化的 P0 首版美术素材，并完成 Manifest 接入、资源包启用、GUI 手动验证步骤。

## 任务背景与痛点
任务19虽然打通了资源包物理子目录与槽位定义，但因 `training_ground_v1` 包配置为 `enabled: false`，且没有落地真实的物理图片，游戏在运行时全部走 fallback 逻辑，因此小游戏界面的视觉表现毫无变化，无法直观确认资源包对齐效果。

## 本任务落地的 P0 实体资源
在 `assets/art-packs/training_ground_v1/` 及其子目录中落地以下 P0 美术图片：

   - `players/player_mecha_cat_idle_01.png`（主角待机）

   - `enemies/enemy_drone_eye_idle_01.png`（机械监视眼，对应 `'enemy.droneEye.normal'`）

## 资源包启用与 Key 重定向覆盖设计
1. 在 `ArtManifest.ts` 中将 `training_ground_v1` 资源包设置为 `enabled: true`。
2. 对已落地的 12 个 Key 去除 `virtual: true` 标记以启动物理存在校验。
3. 在 `ArtResourceResolver.ts` 的 `getArtPath` 内部实现核心 Key 覆盖映射机制：
   - `player.mecha.normal` -> `player.mechaCat.idle`
   - `enemy.rat.normal` -> `enemy.scrapMouse.normal`
   - `enemy.eliteMouse` -> `enemy.scrapGuard.elite`
   - `main.bg` -> `map.trainingGround.floor`
   - 技能图标直接重定向读取对应新槽位下的物理图片。
4. 在 `BackgroundRenderer.ts` 内部，当 `training_ground_v1` 正式包启用时，将大背景的暗色覆盖遮罩透明度由 `0.46` 强化至 `0.78`，从而实现旧巨型机甲背景的低亮度、弱化显示。

## 验证计划
- 运行 `npm run check:art` 确认自检通过且 Physical 实体数显式上升。
- 运行 `npm test` 保证全量 460+ 单测与集成测试通过。
- 引导用户启动微信开发者工具手动在自由探索与固定屏战斗场景下双向确认画面变化。
