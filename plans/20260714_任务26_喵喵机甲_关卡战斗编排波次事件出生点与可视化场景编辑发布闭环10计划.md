# 任务26 关卡战斗编排、波次事件、出生点与可视化场景编辑发布闭环 1.0 计划

## 1. 继承边界
- 已读取任务21至25.1计划、成果说明和当前任务要求。
- 当前正式基线保持 `R000007`，不覆盖 `R000005`、`R000006`、`R000007`。
- 不把任务24.2、25、25.1或26自行判定为 PASS。
- 不用后台模拟或自动测试冒充微信开发者工具人工截图。

## 2. 阶段0收口
- 修复 `GET /api/content/animations/published`。
- 已发布动画预览必须读取当前内容快照声明的 `animationManifestReleaseId` 和 `animationManifestChecksum`。
- 校验 releaseId、checksum 和内容快照发布关系。
- 未声明、缺文件、损坏、release不匹配、checksum错误时返回 disabled 和静态回退原因。
- 增加专项后端测试，覆盖孤立动画快照不启用和合法声明启用。

## 3. 数据模型
- 新增关卡编排模型：布局、图层、出生点、波次、波次条目。
- Prisma 新增 `content_stage_scene_layout`、`content_stage_layer`、`content_stage_spawn_point`、`content_stage_orchestration_wave`、`content_stage_wave_entry`。
- 复用 `content_stage` 作为关卡主表，子表保持可查询引用。
- 少量规则字段使用 JSON，不把整体编排塞进单一 JSON。

## 4. 后端服务
- 新增 Stage Orchestration Service。
- 提供 layout、layers、spawn-points、waves 和事务化 orchestration 保存接口。
- 保存前校验主角出生点、敌人出生点引用、敌人模板、Art Key、波次数量、间隔、上限和乐观锁。
- 删除被波次引用的出生点返回 409 和引用来源。
- 将图层 Art Key、波次敌人、动画覆盖纳入引用查询。

## 5. 发布与快照
- 生成 `content-store/published/stage-orchestration.snapshot.json`。
- 生成 `src/content/generated/stageOrchestrationSnapshot.ts`。
- 内容快照追加 stage orchestration releaseId、checksum 和摘要。
- 正式小游戏只读取内容快照声明的编排快照；老 Release 无声明时回退旧逻辑。
- 新增 `npm run check:stage` 校验编排快照与草稿样例。

## 6. 游戏端
- 新增 `StageDirector`，独立管理状态机、波次、出生点、生成间隔、存活上限、完成和失败。
- 固定屏 `1-1` 优先接入 StageDirector；无正式编排快照时继续使用旧 `WaveManager`。
- 自由探索训练场保持现有逻辑，不强制改造。
- 增加逻辑坐标转换工具和测试，后台与小游戏共用逻辑坐标。

## 7. 管理后台
- 在关卡页增加可视化编排入口与编辑器组件。
- 工作区包含顶部工具栏、左侧资源/对象、中央画布、右侧属性、底部波次列表。
- 支持图层、主角出生点、敌人出生点、波次与条目编辑。
- 增加运行预览，支持开始、暂停、恢复、重置、倍速、击败敌人、跳波和主角死亡。
- 草稿预览标记 MySQL 草稿，已发布预览标记正式快照和回退原因。

## 8. 默认样例
- 在远程 MySQL 草稿中为固定屏 `stage_battle_1_1` 建立三波完整样例。
- 样例包含背景层、地面层、1个主角出生点、3个敌人出生点和3波敌人。
