## 2. 编码前链路实查
- 远程 MySQL `content_art_resource` 存在 `enemy.scrapMouse.normal`，状态为 `physical`。
- 当前草稿版本与发布版本均为 `b30258e1289df7ad536e4ede54dbbaa0`，版本号 v1。
- `content_art_resource_version.storage_path` 指向 `assets/art-packs/training_ground_v1/enemies/enemy_scrap_mouse_idle_01.png`。
- 该版本 `thumbnail_path=null`，这是后台缩略图加载失败的直接触发点。
- 发布 Art Manifest Snapshot 包含 `enemy.scrapMouse.normal`，发布路径为 `assets/art-releases/R000005/enemies/enemy_scrapMouse_normal.png`。
- 基础 `ART_MANIFEST` 包含同 Art Key，物理路径存在，checksum 与发布快照一致。
- 当前后端 `list/get` 返回原始数据库行，未提供统一展示摘要，也未回退快照或基础 Manifest。
- 当前前端使用 `currentDraftVersion ?? publishedVersion` 推导缩略图，缺缩略图路径时不会回退到原图。
- 当前图片接口受 JWT 保护；前端通过 axios Blob 请求携带 Bearer Token 后转 Object URL，适配普通 `<img>` 显示。

## 3. 根因假设
- 主根因：缩略图接口只读取 `thumbnail_path`，历史/迁移版本没有缩略图时直接 404，导致后台各页面无法显示真实缩略图。
- 次根因：后端没有统一资源展示摘要，前端多个位置自行推导状态，无法统一处理草稿、发布、快照、基础 Manifest、Virtual 与 Missing。
- 交互缺口：新建 Art Key 只创建元数据，首张图片上传需另走替换入口，存在空资源半成品风险。

## 4. TDD 修复步骤
- 先补后端红灯测试：缩略图缺失时安全回退原图、基础 Manifest 回退为 Physical、真正缺失返回 Missing、首版本创建失败不留空资源。
- 再补管理端红灯测试：统一摘要字段、首版本向导文件选择与预览、业务字段发起创建后保留绑定上下文。
- 后端实现统一摘要，优先级为草稿版本、发布版本、发布快照、基础 Manifest、Virtual/Fallback、Missing。
- 后端新增首版本创建入口，复用既有上传校验、checksum、缩略图生成和事务写入，不绕过版本安全。
- 前端改为消费统一摘要，缩略图加载使用摘要 URL，保留 Blob 鉴权策略。
- 前端将“新建 Art Key”改为带文件选择的首版本向导，支持从业务字段携带回填上下文。
