# 任务32：首批真实美术替换与任务31.1全量回归收口计划

## 目标与边界

在任务31/31.1既有 Image Library → Art Resource Version → SnapshotGenerator → Release/小游戏链路内，先消除根测试历史断言，再导入首批真实美术、最小换绑并发布。不得重建图库/发布体系，不覆盖原图、Art 历史版本或历史 Release；业务页只可选择、换绑、解除 Art Key，禁止直接上传、改尺寸/Alpha、直接建版本；禁止删除、skip、only、注释屏蔽测试、`as any` 或硬编码 Release。

## 阶段0：开工实测基线（全部保存原始输出）

1. 在根目录执行 `git branch --show-current`、`git rev-parse HEAD`、`git status --short`；无论成功与否，逐条记录 exit code、stdout、stderr（含当前已知 Git 错误），不可把旧成果说明当作实测事实。
2. 执行 `npm run content:db:status`、`node -e "const x=require('./content-store/published/content.snapshot.json');console.log(x.artManifestReleaseId,x.artManifestChecksum)"`；经后台只读 API/数据库记录当前正式 Release、迁移、Art Manifest、资源版本和路径。
3. 运行 `npm test`，逐项记录失败文件、用例、期望、实际及“过期断言/真实回归”分类；只在根测试全绿后才可发布。
4. 读取正式 `content.snapshot.json`、`art-manifest.snapshot.json` 与运行时模型：当前鼠 `enemy_scrap_mouse_01.visual` 使用 `iconArtKey/idleArtKey/moveArtKey/attackArtKey`，均为 `enemy.scrapMouse.normal`；`hitArtKey`、`deathArtKey` 是已存在的可选实际字段。当前主角优先 `player.mechaCat.idle`，第一章/训练场优先 `map.trainingGround.floor`，均须以本次实测为准。

## 阶段1：任务31.1根测试收口（发布门禁）

1. 修复旧任务13固定波次、旧章节/StageSelect、固定 `R000007`、当前 Campaign 快照不兼容断言：波次和历史 Release 用独立 fixture，正式流程读取当前 Campaign/稳定 fixture，不依赖正式编号。
2. 保留并补齐正式 Campaign 入口、free-map Stage、固定屏仅调试入口、历史 Release fixture、Tutorial 初始化/推进，以及旧 StageSelect 明确替代流程测试；`TutorialManager.getStep()`、`getTargetArea()` 必须在真实运行时初始化后可调用。
3. 全量 `npm test` 必须通过；任何失败都列出并阻断发布，不能把旧失败归入本任务已通过。

## 阶段2：真实美术生成、来源与图库导入

1. 用图像生成工具制作鼠 idle/move/attack/hit/death、主角至少 idle、第一章/训练场至少 floor；每项记录生成源文件绝对路径 `content-store/art/task32-source/<对象>/<状态>.png`、生成日期、提示词摘要、权属为“AI 生成、项目可用”、SHA-256 和人工视觉复核。源文件只作可追溯原图，不直接写入 Art/Release 目录。
2. 鼠图统一 PNG、透明真实 Alpha、64×64、nearest + contain、透明留白，保持朝向、脚底线和主体比例；主角同一动作帧画布/锚点一致；场景先按实测 `world-tile`/画布策略生成，严禁强制 64×64。
3. 从管理端“图库”上传上述源文件（或现有受控批量上传 API），不是文件系统直写；逐项保存 assetId、原图路径、MIME、宽高、Alpha、checksum、缩略图、去重结果。为鼠图在图库用 Sharp 创建 64×64 派生 variant，并实测可解码、`image/png`、真实 Alpha、独立 checksum、原图未变。

## 阶段3：Art 版本、状态最小绑定与引用

1. 从图库 asset/variant 创建草稿 Art Resource Version，逐项保存 `assetId/variantId/versionId/storagePath/mimeType/width/height/hasAlpha/checksum/validationStatus`；刷新和重启 NestJS 后草稿仍在，删除草稿不得删除图库源。
2. 先复核当前鼠 `normal` 与动画 clip。仅在渲染器已按字段解析且完整校验通过时，为实际状态最小新增/绑定状态 Art Key：`idle/move/attack` 沿用现有 normal 或独立 Key；受击必须绑定 `visual.hitArtKey`，死亡必须绑定 `visual.deathArtKey`。不得以新协议或只改字段名伪造五态；若某状态无实际运行入口，保留为未验证并说明。
3. 业务页仅换绑鼠五态、主角状态和第一章场景 Art Key；对每个 Key 执行“查看全部引用”，中文对象/字段、摘要数与详情数一致，且业务页仍无上传/处理入口。

## 阶段4：发布前校验、正式发布与终态审计

1. 调用 `npm run content:validate`，保存完整 JSON；必须 `valid=true`、`errorCount=0`、`warningCount=0`，并覆盖图库源/派生、Art 版本、五态字段、动画、free-map、Tutorial、Campaign。不得降级或隐藏错误。
2. 发布前记录 R14、R15 的 releaseId、Art Manifest checksum、资源 `versionId/path/checksum`；发布仅用 `npm run content:publish`，由系统生成新编号。保存发布响应及新 Release 的 asset/variant/version/path/metadata/checksum；以 SHA-256/Manifest 条目逐项比较 R14、R15 的历史目录与 hash 未变，并记录新版本资源已变。
3. 保存发布后完整校验 JSON、Art Manifest JSON/TS、content/animation/stage/campaign/tutorial 快照及构建 probe；发布失败或任何 hash 比较异常不得切正式指针。

## 阶段5：真实验证命令与小游戏证据

1. 根：`npm run typecheck`、`npm run build`、`npm test`、`npm run check:art`、`npm run check:content`、`npm run check:animation`、`npm run check:stage`、`npm run check:campaign`、`npm run check:tutorial`。
2. 服务端：`npm --prefix server run content:db:generate`、`npm --prefix server run content:db:status`、`npm --prefix server run typecheck`、`npm --prefix server run build`、`npm --prefix server run test`、`npm --prefix server run test:e2e`；在 `server` 目录执行 `npx prisma validate` 并记录输出。
3. 管理端：`pnpm --dir admin/apps/web-antd typecheck`、`pnpm --dir admin/apps/web-antd test`、`pnpm --dir admin/apps/web-antd build`。每个命令记录 cwd、exit code、通过/失败/警告；缺命令或环境阻塞如实写 BLOCKED。
4. 仓库无可替代微信“构建”CLI 时，不虚称 CLI 通过：在微信开发者工具清缓存、重新编译项目，保存控制台和运行时 probe（releaseId、artManifestReleaseVersion/checksum、loadedArtResourceCount、鼠五字段 Art Key、heroArtKey、floorArtKey、stageRuntimeMode），确认只读新正式 Release/Manifest、无 404/Missing/Invalid/checksum mismatch。
5. 区分 HTTP 服务端口和 `miniprogram-automator` WebSocket 自动化端口：先通过官方 `cli.bat auto --project <root> --auto-port <port>` 启动实例，再以 `WECHAT_AUTOMATOR_PORT=<port> npm run test:gui:wechat` 运行截图断言；端口不得硬编码为 HTTP 服务端口。
