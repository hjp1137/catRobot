# 关卡配置列表分页资源响应兼容修复计划

## 问题与根因

- 管理端“关卡配置”初次获得关卡数据后，会继续加载美术资源预览。
- `/content/resources` 已返回分页对象 `{ items, page, ... }`，而 `contentApi.resources()` 与调用方仍按数组使用。
- `EntityListView.loadResources()` 调用 `artResources.value.map` 抛出异常；外层 `load()` 捕获后将已显示的关卡记录清空。

## 最小修复

1. 在 `contentApi.resources()` 统一解包分页响应，保持调用方的数组契约。
2. 先增加 API 包装层回归测试，覆盖数组与 `{ items }` 两种服务端响应。
3. 验证关卡列表预览加载不再触发资源 `.map()` 异常。

## 验收

- 关卡配置刷新后两条记录稳定保留。
- 资源预览、动画编排等既有数组调用方继续正常。
- 管理端类型检查与测试通过。
