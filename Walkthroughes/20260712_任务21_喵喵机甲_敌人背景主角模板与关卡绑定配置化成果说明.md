# 任务21 敌人背景主角模板与关卡绑定配置化成果说明

## 1. 执行结论
已建立内容模板系统，固定屏 `1-1` 和自由探索训练场已通过 StageDefinition 绑定敌人、背景主题和主角表现。当前主数据源为 `src/content/data/*.ts`，旧 `StageConfig`、`EnemyConfig` 保留为兼容层。

## 2. 修改文件列表

- 新增：`src/content/models/*`、`src/content/data/*`、`src/content/repositories/*`、`src/content/registry/ContentRegistry.ts`、`src/content/validation/*`、`src/content/adapters/*`。
- 新增：`scripts/check-content-config.cjs`、`test/contentRegistry.test.ts`、`test/contentValidation.test.ts`、`test/stageContentBinding.test.ts`。
- 新增：`docs/20260712_喵喵机甲_内容模板与关卡配置说明.md`、本成果说明。
- 修改：`package.json`、`StageConfig.ts`、`EnemyConfig.ts`、`EnemyMouse.ts`、`BattleManager.ts`、`ResourceManager.ts`、`BackgroundRenderer.ts`、`MechaRenderer.ts`、`Chapter2EnemyRenderer.ts`、`ExploreContentConfig.ts`、`ExploreEnemySystem.ts`、`ExploreScene.ts`、`ExploreRenderer.ts`、`BattleUI.ts`、`main.ts`、探针文件。

## 3. 内容系统总体架构

`LocalContentRepository` 加载本地纯数据，`ContentRegistry` 负责集中 ID 查询和冻结模板，运行时通过 `StageDefinition` 解析敌人模板、背景主题和主角表现。Art Key 仍交给 `ArtManifest` 与 `ArtResourceResolver` 解析。

## 4. EnemyTemplate

已建立 4 个模板：`enemy_scrap_mouse_01`、`enemy_scrap_bug_01`、`enemy_drone_eye_01`、`enemy_scrap_guard_elite_01`。废料鼠与精英守卫数值迁移自现有机械鼠/强化机械鼠配置。

## 5. BackgroundTheme

已建立 `background_training_ground_v1` 与 `background_forging_corridor_v1`。训练场主题控制网格、区域标记和边界显示；铸造通道主题用于固定屏 `1-1`。

## 6. HeroVisualTemplate

已建立 `hero_mecha_cat_default`，主角 idle/move/attack 和技能按钮图标均通过 Art Key 配置。

## 7. StageDefinition

已建立 `stage_battle_1_1` 和 `stage_explore_training_01`。固定屏三波敌人和自由探索 4 个刷新点已迁移到关卡定义中。

## 8. ContentRepository

已建立 `ContentRepository` 接口和 `LocalContentRepository` 实现。后续后台可新增 `ApiContentRepository` 替换本地数据源。

## 9. ContentRegistry

已建立集中查询 API：`getEnemy`、`getBackground`、`getHeroVisual`、`getStage` 和对应 list 方法。缺失 ID 会抛出明确错误。

## 10. 配置校验

已新增 `npm run check:content`。校验 ID、name、version、enabled、数值范围、Art Key、模板引用、禁用模板引用和探索刷新点坐标。

## 11. 固定屏关卡迁移

`STAGE_1_1` 由 `LegacyStageConfigAdapter` 从 `stage_battle_1_1` 生成兼容 `StageConfig`。`BattleManager` 生成敌人时优先使用 `enemyTemplateId`。

## 12. 自由探索迁移

`TRAINING_GROUND_CONTENT.spawnPoints` 由 `stage_explore_training_01.exploration.spawnGroups` 派生。刷新系统通过 `enemyTemplateId` 创建敌人。

## 13. 敌人数值迁移

`createEnemyConfigFromTemplate()` 将模板 stats/combat/visual 转为旧实体可消费配置。运行时敌人实例带 `contentTemplateId` 与 `visual.idleArtKey`。

## 14. 美术 Key 迁移

`ResourceManager` 新增训练场主角、敌人、地图资源键和 `getImageByArtKey()`。敌人、主角、技能按钮、背景均优先按模板 Art Key 取图。

## 15. 旧硬编码清理说明

固定屏 `1-1` 和自由探索训练场不再以散落波次数组/刷新点硬编码作为主源。旧章节、Boss 召唤、进度、掉落仍依赖旧 `StageConfig` 与 `EnemyConfig`。

## 16. 暂时保留的兼容层

`StageConfig`、`EnemyConfig`、`LegacyStageConfigAdapter`、`EnemyTemplateAdapter` 暂时保留。它们用于兼容历史章节与现有战斗实体，不作为新关卡扩展入口。

## 17. 调试探针

新增 `__MEOW_CONTENT_TEST_STATE__`，字段包括 repositoryType、loaded、模板数量、activeStageId、activeBackgroundThemeId、activeHeroVisualTemplateId、activeEnemyTemplateIds、validationPassed。自由探索探针也输出 active 模板字段。

## 19. 用户手动 GUI 验证步骤

1. 运行 `npm run build`，打开微信开发者工具并刷新项目。
2. 进入自由探索，确认玩家、敌人、背景、HUD、技能按钮正常。
3. 返回并进入固定屏战斗 `1-1`，确认三波敌人数量和波次提示正常。
4. 临时修改 `enemy_scrap_mouse_01.stats.maxHp` 或 `moveSpeed`，构建刷新后确认击败耗时或移动速度变化，测试后恢复。
5. 临时修改废料鼠 `visual.idleArtKey`、关卡 `backgroundThemeId`、固定屏某波 `enemyTemplateId`、主角 `visual.idleArtKey` 或技能图标 Key，确认无需改渲染器即可变化，测试后恢复。
6. 建议截图：自由探索初始画面、固定屏第一波、`check:content` 成功日志、修改数值/美术/背景/敌人绑定后的画面。
