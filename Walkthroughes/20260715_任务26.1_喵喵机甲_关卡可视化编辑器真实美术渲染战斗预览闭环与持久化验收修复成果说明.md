# 任务26.1成果说明

## 1. 执行结论

已在任务26既有数据模型、Prisma migration、StageDirector、发布快照和后台框架上完成增量修复，并形成代码、全量测试、远程 MySQL、真实浏览器及 22 张截图证据。本说明仅提交审核事实，不自行给出 PASS/FAIL 结论。

1. 静态画布改为真实 Art Key 图片、图层和对象渲染。
2. 属性面板接入布局、图层、出生点、波次和条目真实表单。
3. 出生点支持鼠标拖动、坐标输入、键盘微调、复制和删除。
4. 图层支持新增、编辑、排序、显隐及资源错误提示。
5. 波次和条目支持新增、复制、删除、排序及全字段编辑。
6. 预览状态覆盖准备、运行、波次完成、暂停、通关和失败。
7. 草稿与已发布预览分离，R000007 不读取 MySQL 草稿。
8. 保存、刷新、Nest 重启后的数据均由远程 MySQL 恢复。
9. 双页面制造 rowVersion 冲突并保留本地编辑。
10. 测试结果补齐数量、专项明细、日志及浏览器错误统计。

## 3. 实际工程检查

- 任务26原编辑器为 89 行静态骨架，未形成真实编辑和预览闭环。
- 后端已有事务、rowVersion、编排表和 StageDirector，均原位扩展。
- 远程 MySQL 为 `124.221.17.54:3306/cat_robot`，5 个 migration，schema 为最新。
- R000007 内容快照没有 Stage Orchestration 声明，正式运行必须保留旧逻辑。
- 未创建任务27能力，未覆盖任何历史发布目录，未发布新 Release。

## 4. 真实美术渲染实现

- 通过现有资源摘要/缩略图接口获取 blob URL，不旁路硬编码图片路径。
- 画布显示训练场地面、主角机甲和敌人正式资源，并按图层顺序、坐标和比例绘制。
- 缺失或非法 Art Key 显示明确状态；后端保存时拒绝启用的非法图层资源。
- `frontend-design` 约束用于延续现有深色工业机甲视觉，不改变产品整体视觉语言。

## 5. 编辑器布局修复

页面由对象树、场景画布、属性检查器、波次编辑器和战斗预览区组成。窄屏可换行，属性区不再用静态 JSON 冒充表单。

## 6. 出生点拖动与坐标编辑

- GUI 真实鼠标拖动后坐标变化；坐标输入最终保存为 `enemy_left=(333,444)`。
- 方向、启用状态、网格吸附及键盘方向键微调已接入。
- 输入框聚焦时不会触发画布键盘移动。
- 复制产生独立对象；删除被波次引用的出生点会得到结构化 409。

## 7. 图层编辑

支持名称、Art Key、层级、位置、尺寸、透明度、可见性、新增、复制、删除和排序。GUI 新增了明确命名的草稿测试图层，保存刷新后仍存在，未进入发布快照。

## 8. 波次和条目编辑

- 波次支持名称、开始延迟、最大存活、完成延迟、启用、复制、删除和排序。
- 条目支持敌人模板、出生点、数量、初始延迟、生成间隔、精英标记、等级/生命/攻击倍率和启用状态。
- 实测第一波保存为 `第一波-26.1验收`、最大存活 4、数量 4、间隔 650ms、倍率 1.2/1.1/1.3。

## 9. 保存刷新重启闭环

GUI 保存前 rowVersion 15，保存后 16，刷新后仍为 16；双页面后远端更新为 17。关闭并重启 Nest 服务后重新登录页面，rowVersion 17、坐标和波次参数均保持。

## 10. 远程 MySQL 持久化

`server-db-status.log` 证明连接远程 `cat_robot` 且 5 个 migration 全部最新；`remote-mysql-persistence.json` 记录重启后 API 回读值。本任务没有新增 migration。

## 11. rowVersion 与 409

两个独立浏览器页面同时读取版本，页面B先保存至 17，页面A再保存得到 `CONTENT_CONFLICT`。页面A显示本地/远端版本，保留未保存值并提供重新载入远端数据操作。

## 12. 未保存提示

修改表单后离开路由会弹出确认框；刷新或关闭页签也注册 `beforeunload`。保存成功后 dirty 状态清除。

## 13. 撤销与重做

编辑会写入本地历史栈；工具栏按钮按历史状态禁用，实际修改可撤销并重做，保存后建立新基线。

## 14. 战斗模拟状态机

独立模拟器按编排运行 `READY → PREPARING → WAVE_RUNNING → WAVE_CLEAR → PREPARING`，支持暂停、恢复、跳过等待、1x/2x/4x、重置和释放。画布复用真实背景、主角、敌人及出生点数据。

## 15. STAGE_CLEAR 闭环

真实浏览器依次清除三波并进入 `STAGE_CLEAR`；截图显示第三波、真实敌人和最终状态，结束后不再生成敌人。

## 16. STAGE_FAILED 闭环

真实浏览器在运行态触发主角死亡并进入 `STAGE_FAILED`；后续 tick 不改变终态，也不继续生成敌人。

## 17. 草稿和已发布隔离

草稿预览显示远程 MySQL 三波编排和草稿测试层；已发布预览调用独立 published API，不复用编辑器内存草稿。两种来源分别截图。

## 18. R000007 回退验证

published API 校验当前内容快照、Stage Orchestration snapshot 和 checksum。R000007 未声明该能力，返回 `enabled=false`、原因 `content-snapshot-stage-orchestration-not-declared`，界面明确显示旧逻辑回退，不展示草稿三波。

## 19. 引用保护

- 删除 `enemy_right` 出生点时，后端返回 `CONTENT_REFERENCE_EXISTS`，包含 waveId、entryId、enemyTemplateId 和字段来源。
- 保存启用图层时校验 Art Key；无效或缺失资源会阻止保存。
- 既有敌人模板、Art Key、Animation Clip 引用查询逻辑保持复用，未建立第二套引用系统。

## 20. StageDirector 验证
