# 任务16 成果说明：全局界面人物场景与特效美术升级

## 目标
增量升级全局视觉，覆盖主界面、章节、关卡、关卡介绍、战斗、技能养成、装备和结算界面。接入20个新增美术资产。实现全局UI自适应重构以兼容不同尺寸和DPR。

## 完成内容
1. 20个新增美术资产（包含下水道背景、6种敌人变体、9种装备、3种符文、1个中毒状态）的接入与兜底。
2. 封装与统一 `src/ui/UIWidgets.ts` 中 `drawTitle`、`drawPanel`、`drawButton` 等通用视觉组件。
3. 全局 8 个界面（MainUI, ChapterSelectUI, StageSelectUI, StageIntroUI, BattleUI, SkillPanelUI, EquipmentPanelUI, ResultUI）的 UI 动态自适应与 DPR 参数化排版重构。
4. 中毒特效图片（`status_poison.png`）优先渲染以及资源解析公共化。

## Node模拟器验证
1. **20张新增素材实际绘制与分类兜底**：验证加载成功时正确渲染，加载失败时启动程序化兜底（测试运行时临时改写为失败路径，不存在实体 `_fail.png` 素材文件）。
2. **11个真实敌人变体**：全量变体支持图片渲染与形状兜底。
3. **三组尺寸/DPR**：通过测试在 320x568 (DPR 1), 375x667 (DPR 2), 414x896 (DPR 3) 尺寸下自适应排版。
4. **八界面边界与命中**：MainUI, ChapterSelectUI, StageSelectUI, StageIntroUI, BattleUI, SkillPanelUI, EquipmentPanelUI, ResultUI 的点击热区与画布不溢出边界断言全通过。
5. **三章胜负链路**：战斗成功、失败结算及主循环链路正常。
6. **资源加载去重/失败收敛**：已加载资源重新载入时不重复创建 Image 实例。
7. **任务15存档重启**：保存并在新 GameManager 重载后战力数值维持 385 且数据属性完全吻合，无新增存档字段或改变旧存档格式。

## 发现的问题
- **分辨率溢出缺陷**：主界面（MainUI）硬编码底边缘 `592` 以及关卡介绍（StageIntroUI）硬编码按钮坐标导致在 320x568 小屏幕上按钮溢出，已重构为基于 `canvasHeight` 动态布局组件，彻底杜绝溢出缺陷。
