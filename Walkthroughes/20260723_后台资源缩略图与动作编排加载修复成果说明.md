# 后台资源缩略图与动作编排加载修复成果说明

## 根因

- `ArtResourceSelector` 将 API 已归一化的数组再次当作分页对象读取 `.items`，资源列表变为 `undefined`，触发 `filter/map` 异常并误报已存在帧为 `Invalid资源`。
- 资源版本记录可能保留缺失的 WebP 缩略图路径；接口未验证该文件即交给 `sendFile`，造成浏览器 500 和 15 秒超时。

## 修复

- 选择器直接消费 `contentApi.resources()` 的数组返回值，恢复动作帧资源筛选。
- 缩略图请求发现文件缺失时，服务端从有效原图补建指定尺寸 WebP；原图也缺失时抛出明确的 404，而不是文件系统 500。
- 资源列表会短暂缓存已解析版本，随后的并行缩略图请求不再逐张占用远程 MySQL 单连接。
- Prisma 连接池由 1 条调整为 4 条；资源详情也复用列表摘要，避免重复 `findUnique`。
- 动作预览缩略图对成功、失败和进行中请求按 Art Key 去重，切帧不再形成请求循环。
- 增加前端数组响应回归断言，以及后端缺缩略图自动补建回归用例。

## 验证

- 管理端 `typecheck`、`test`：19 文件、69 用例通过。
- 服务端 `typecheck`、缩略图版本回归：18 用例通过。
- `npm run check:art`：0 Missing、0 Checksum、0 Dimension 错误。
- `npm run check:animation`：3 个 Clip、6 个帧资源通过。

## 使用说明

3100 服务已按新配置启动并通过健康检查。刷新后台“动作编排”页面即可清除浏览器中断服务期间的失败请求；首次遇到历史缺失缩略图会生成轻量 WebP，随后请求直接复用该文件。
