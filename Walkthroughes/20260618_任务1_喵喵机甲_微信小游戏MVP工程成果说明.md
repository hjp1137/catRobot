## 八、技术决策记录

- **为何不采用 Cocos Creator**：当前工程是原生微信小游戏工程，本机无 Cocos 编辑器无法本地闭环验证。原生小游戏 + Canvas 2D + TypeScript 可在 Node 下做完整单测，最符合「禁止让用户充当测试员」原则。
- **为何引入 IContext 抽象**：把 wx/DOM/Node 三种运行时统一为接口，使 BattleManager/PlayerMecha 等纯逻辑类可在 Node 单测中用 MockContext 驱动，实现「能在本地验证」。
- **为何测试 import dist 而非 src**：Node 原生 strip-types 走 ESM 解析要求显式扩展名，src 的 import 无扩展名会失败；改测 dist 编译产物既绕开此问题，又能顺便验证编译产物可用。
