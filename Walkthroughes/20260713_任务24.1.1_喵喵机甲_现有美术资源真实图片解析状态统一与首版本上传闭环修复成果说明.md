# 任务24.1.1 喵喵机甲现有美术资源真实图片解析状态统一与首版本上传闭环修复成果说明

## 1. 执行结论
- 已修复 `enemy.scrapMouse.normal` 等历史物理资源在后台无法展示真实缩略图的问题。
- 已统一资源列表、详情、选择器和业务字段使用同一套后端展示摘要。
- 已补齐“新建 Art Key + 首版本图片上传 + 当前草稿绑定”的闭环接口和前端入口。
- 未新增数据库 migration。

## 2. 根因定位
- 任务24导入的 `enemy.scrapMouse.normal` 版本存在 `storage_path`，但 `thumbnail_path` 为空。
- 后端缩略图接口只读取 `thumbnail_path`，导致真实 PNG 存在但接口返回 404。
- 前端多个页面自行拼接状态、版本和图片地址，历史物理资源被错误展示为空图或不一致状态。

## 3. enemy.scrapMouse.normal 数据链路
- 远程 MySQL：`resource_status = physical`。
- 当前草稿版本与发布版本相同：`b30258e1289df7ad536e4ede54dbbaa0`。
- 原图路径：`assets/art-packs/training_ground_v1/enemies/enemy_scrap_mouse_idle_01.png`。
- 发布目录同 checksum 文件存在：`assets/art-releases/R000005/enemies/enemy_scrapMouse_normal.png`。
- live API 验证：`/api/content/resources/enemy.scrapMouse.normal/thumbnail` 返回 `200 image/png 16516 bytes`。

## 4. 资源状态统一规则
- 优先级：MySQL 草稿版本、MySQL 发布版本、发布 Art Snapshot、基础 Art Manifest、virtual、missing。
- 物理文件缺失时标记 `missing`。
- checksum 不一致时标记 `invalid`。
- 后端统一返回 `status`、`source`、`displayVersion`、`thumbnailUrl`、`originalUrl`、尺寸、MIME、checksum、未发布变更标记。

## 5. 图片接口修复
- `thumbnail` 请求在 `thumbnail_path` 为空时回退 `storage_path`。
- 新增按 Art Key 直接访问的 `/thumbnail` 与 `/preview` 接口。
- 保留版本级 `/versions/:versionId/thumbnail` 与 `/preview`。

## 6. 前端显示修复
- 美术资源图库、表格、详情、选择器、业务字段、预览卡片统一使用后端 `thumbnailUrl` 与 `status`。
- 敌人列表和编辑抽屉资源字段改为读取统一摘要，不再按旧字段猜测图片来源。
- “查看原图”使用 `originalUrl`。

## 7. 首版本向导实现
- 新增 `POST /api/content/resources/create-with-version`。
- 前端新建资源抽屉新增图片选择、上传前预览和首版本上传。
- 从业务字段进入“上传新资源”时携带 `bindKind`、`bindId`、`bindPath`，创建成功后回写业务字段并返回原业务页。
