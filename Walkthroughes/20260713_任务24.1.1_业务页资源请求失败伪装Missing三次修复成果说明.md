# 任务24.1.1 业务页资源请求失败伪装 Missing 三次修复成果说明

## 1. 现场结论
- Chrome 当前页真实运行的是 Vite 源码，不是旧构建包。
- 页面已发出 `/api/content/resources/:artKey` 请求。
- 控制台出现 `AxiosError`，Vue mounted hook 被打断。
- 刷新当前 Chrome 页后，新逻辑将页面带回 `/login`，确认当前会话 token 已失效。

## 2. 根因
- 后端 3100 资源接口和远程 MySQL 数据均正常，资源状态为 `physical`。
- 旧前端没有处理 401，也没有区分请求失败与资源缺失。
- `ArtResourceField` 和 `ArtResourceThumb` 把请求失败后的空 resource 显示为 `missing`，误导为图片不存在。

## 3. 修复
- `api/client.ts` 增加响应拦截器：401 时清除 `cat_robot_token` 并跳转 `/login`。
- `EntityListView` 捕获内容列表和资源列表加载失败，避免 mounted hook 未处理异常。
- `ArtResourceField` 增加 `loadError` 状态，请求失败时显示“加载失败”。
- `ArtResourceThumb` 增加 `loadError` 支持，请求失败时不再显示 `missing`。
- 父级资源列表失败时，由登录跳转或字段级错误状态接管，不再误报资源缺失。

## 4. 当前操作要求
- 当前 Chrome 已回到登录页。
- 重新登录后再进入敌人、背景、主角或关卡页，资源接口会携带新 token 拉取真实缩略图。
