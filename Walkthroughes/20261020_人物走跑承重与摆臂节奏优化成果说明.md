# 人物走跑承重与摆臂节奏优化

日期：2026-10-20。按用户澄清，以正式 Godot 游戏为目标；四向预览只辅助验证同类运动关系。

## 正式游戏修改

- 复用现有位移、方向判断、分件、装备与足部接地点链，只修改 `godot/scripts/player_motion_rig.gd`。
- 摆臂跟随实际同侧脚的前后位置，修正同手同脚；增加跑动前倾、回收时弯肘和足掌滚动。
- 跑步周期步幅比从 0.65 调整到 0.82，适度降低原来的碎步频率；实际游戏速度和碰撞逻辑不变。
- 将走路越过支撑腿、跑步落地缓冲和腾空抬升分开。原运行分支对整个身体上升限速，曾把飞行中点压在下沉位置；现只平顺释放额外的可达性补偿。
- 摆腿提前回收，落地前伸出。摆动脚也受真实腿长范围约束，避免侧面 IK 被截断、正背面小腿被拉长。
- 前后腿的膝、踝分阶段运动；落点和提前离地考虑投影可达范围，保留素材尺寸与世界排序。
- 蹬地、回收和停步之间保留足掌角度衔接；首步抬脚收敛，修复斜向重开突跳。
- 停稳高度按两只脚的实际位置计算。图形记录曾发现正面停步瞬间腿长达到约 145.4，已补充停步腿长回归。

## 本地验证

- 最终 Godot 导入通过，8 组检查共 **1713 PASS / 0 FAIL**：节奏79、自然动作261、斜向214、模块动作279、动作碰撞113、战斗46、双武器156、营地565。
- 新回归覆盖实际肩到腕反向摆动、足掌切换角连续、真实移动帧中的承重/腾空起伏、摆动可达性与停步腿长；未只用静态姿态替代运行验证。
- 旧实现节奏红例与后续真实分支红例保留在 `logs/20261020_gait/`，最终结果在 `final/`。最终检查同时检查脚本/引擎错误与资源泄漏。
- 更长 GPU 序列使用真实 Battle 键盘输入与地图位移：四向、斜向、混装与全甲，共7段，每段252个60Hz控制步、126张30fps采样。
- 每段慢走1秒、跑2秒、停0.4秒、重开0.4秒、再停0.4秒。采样选择经真实地图检查的通路，并断言活动输入产生位移，避免把被管道阻挡的站立误当跑步。
- 最终 GPU 检查 **4261/0**，1764个控制步、882张采样；7段视频各126帧完整解码。全程各向腿部投影总长最大132，承重脚关节最大世界滑移0.000273像素，目标误差0.000126像素。
- 实际稳定奔跑中，侧面/正面/背面的骨盆偏移均约2.00–25.22源像素，验证腾空曲线未再被真实运行分支压平。主代理查看了最终四向/斜向关键帧；浏览器7段加载、半速和逐帧操作通过，0异常。
