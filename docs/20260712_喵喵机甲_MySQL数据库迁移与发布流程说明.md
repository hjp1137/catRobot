# 喵喵机甲 MySQL 数据库迁移与发布流程说明

## 1. 目标库

- Product：MySQL Community Server
- 目标版本：8.0.33
- 数据库：`cat_robot`
- 本次不升级远程 MySQL，不删除或重建数据库。

## 2. 迁移文件

Prisma schema：

```text
server/prisma/schema.prisma
```

Migration：

```text
server/prisma/migrations/202607120001_content_admin_init/migration.sql
```

迁移只创建 `content_` 前缀表，不包含 `DROP DATABASE`、`migrate reset` 或 `db push --force-reset`。

## 3. 迁移前检查

配置 `server/.env` 后执行：

```sql
SELECT VERSION();
SELECT DATABASE();
SHOW VARIABLES LIKE 'character_set_database';
SHOW VARIABLES LIKE 'collation_database';
```

也可通过：

```bash
curl http://127.0.0.1:3100/api/health/database
npm run content:db:status
```

如果返回数据库不是 `cat_robot`，停止迁移。

## 4. 安全执行

```bash
npm run content:db:generate
npm run content:db:status
npm run content:db:migrate
```

远程库只允许使用 `prisma migrate deploy`。

## 5. 初始化数据

```bash
npm run content:db:seed
npm run content:art:sync
```

Seed 来源为任务21本地配置：敌人 4 条、背景 2 条、主角 1 条、关卡 2 条。Art 同步来源为 `src/assets/ArtManifest.ts`。

## 6. 草稿修订

后台新增、编辑、复制、启停和删除内容时：

- 写入 MySQL 草稿表；
- `content_system_state.draft_revision` 递增；
- `draft_dirty` 置为 true；
- 写入 `content_change_log`。

## 7. 发布流程

```text
后台编辑
→ MySQL 草稿
→ /api/content/validate
→ /api/content/publish
→ content_release
→ content_release_snapshot
→ contentSnapshot.ts 与 content.snapshot.json
→ npm run build
```

校验失败禁止发布。文件写入失败时，发布记录标记为 failed，旧快照文件保留。

## 8. 恢复流程

历史版本恢复只执行：

```text
content_release_snapshot → MySQL 草稿
```

恢复后必须重新校验、重新发布，不能直接覆盖当前游戏发布配置。
