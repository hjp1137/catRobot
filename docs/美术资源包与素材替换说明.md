# 《喵喵机甲》美术资源包与素材替换说明

本文档用于说明游戏的美术资源架构、命名规范、Manifest 配置、以及后续如何新增或替换游戏内的图片素材。

## 1. 美术资源目录结构
新版美术资源必须按照类型放置在 `assets/` 对应的子目录中：
- `assets/art/players/`：主角/机甲相关图片。
- `assets/art/enemies/`：老鼠、变体怪物等敌人图片。
- `assets/art/maps/`：世界地图、背景大图。
- `assets/art/ui/`：技能图标、背包、装备、界面用图。
- `assets/art/placeholders/`：占位兜底图。

## 2. 素材命名规范
所有图片文件命名必须使用**全英文、小写、下划线**分隔，禁止使用中文、空格和随机哈希。
规范格式：`类型_对象_状态_序号.png`
- 示例：`player_mecha_cat_idle_01.png`
- 示例：`enemy_scrap_mouse_elite_01.png`
- 示例：`ui_skill_shield_01.png`

## 3. Art Manifest 资源配置机制
所有的资源引用在代码中都是使用统一的 `ArtResourceKey`（类型安全的字符串 Key），而不是硬编码物理路径。
所有的映射关系登记在 `src/assets/ArtManifest.ts` 中。

配置示例：
```ts
'enemy.rat.normal': { 
  path: 'assets/enemy_rat.png', 
  type: 'sprite', 
  pack: 'base', 
  fallback: 'placeholder.image' 
}
```
配置字段含义：
- `path`：资源的物理路径（相对于项目根目录）。
- `type`：资源类型（`sprite` | `icon` | `background` | `placeholder` | `status`）。
- `pack`：资源包所属名称（如 `'base'`，`'prototype'`）。
- `fallback`：当该图片在物理磁盘上未找到或加载失败时，递归退回的备用资源 Key。
- `virtual`：如果设为 `true`，则说明该资源为程序化动态自绘素材，自检脚本将自动跳过物理文件存在性检测。

## 4. 如何进行素材管理与替换

### A. 如何替换已有素材（如老鼠普通敌人）
1. 准备好你的新图片 `enemy_rat.png`。
2. 将其复制覆盖到 `assets/` 下（或放在 `assets/art/enemies/` 中）。
3. 如果改变了物理文件名或位置，直接修改 `src/assets/ArtManifest.ts` 中对应的 `path` 值。
4. 运行 `npm run build` 和 `npm run check:art` 确认检查通过即可，无需修改任何渲染层或业务层代码。

### B. 如何新增一个美术素材并投入使用
1. 将你的图片放入对应的子目录中。
2. 在 `src/assets/ArtResourceKeys.ts` 中追加声明一个新的 `ArtResourceKey` 类型（如 `'enemy.boss.dragon'`）。
3. 在 `src/assets/ArtManifest.ts` 的 `ART_MANIFEST` 配置中注册该 Key 及物理路径映射。
4. 在代码中通过 `getArtPath('enemy.boss.dragon')` 或是调用 `ResourceManager` 传入 Key 直接使用该素材。

## 5. 资源缺失完整性自检
在进行版本发布或构建前，可以通过以下命令快速扫描 Manifest 以校验是否存在丢失的图片文件：
```bash
npm run check:art
```
如果存在缺失，终端会清晰列出发生卡点错漏的 Key 及其路径，并抛出 `exit 1` 阻断构建。
