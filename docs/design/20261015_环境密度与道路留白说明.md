# 环境密度与道路留白说明

日期：2026-10-15。范围仅为 Godot 十关地图内的小型工业实体与地面分区。

## 问题与布局取舍

地图面积已经放大，原来的大型机器仍停留在稀疏阵列中，沿路容易出现整屏只有重复地板的情况。这次增加沿路的检修、管线、废料与供能小组合，保留移动和交战的留白。

新增实体继续放在 `profile.obstacles`，使用现有地图、碰撞和寻路数据。没有使用可穿过的直立设施假装场景密度，也没有移动原有大型机器。

四类实体：`service` 为检修设备，`pipework` 为落地管线组合，`scrap_heap` 为废料堆，`pylon` 为供能立柱。碰撞占地分别约为 110×90、150×84、100×76、64×88。

优先在出生区可见边缘和道路两侧布置；邻近实体分散成组，禁止为了凑数量侵入道路和目标空间。两侧摆放留出实际绕行余地，并保持少量开放岔路。

## 主路与玩法点留白

- 所有原道路矩形向外再保留 34 像素，不放新增实体，匹配导航检查半径。
- 出生点保留半径 180 像素；宝箱保留 140 像素；中继保留 400 像素；首领点保留 500 像素。
- 危险区和加速区的原矩形向外保留 34 像素。
- 新实体与原实体、新实体之间至少保留 75 像素的矩形间隔，避免可见狭缝实际无法通过。
- 首关保留既有动作碰撞验证区、出生上下左右行走区、工业遮挡镜头，以及从 (313, 513) 到 (1507, 513) 的原寻路场景。

保留旧 `rect` 的值与顺序、地图尺寸、出生点、道路、地标、宝箱、地形区域、敌人参数和通关条件。

## 地面分区接口

每图新增 `profile.environment = {seed, districts}`。五个分区分别围绕出生检修泊位、左侧回收装卸区、右上供能支线、中段受损接驳带与首领外围布置。

每项为 `{name, kind, rect}`，`kind` 使用 `service / cargo / power / damage`。矩形只提供地面细节的分布范围，由 renderer 以分散格栅、线缆、修补板、污迹和金属碎屑表现，不绘制整块矩形地毯，也不新增碰撞。

## 本次布局验证

本地静态验证按现有 40 像素导航格和 34 像素障碍膨胀规则计算，检查十图全部开放格与出生点保持单一连通，且所有宝箱、中继和首领位置可达，全部通过。

另外逐项比较原有数据不变，检查四类实体齐备、每图 50～90 个新增实体、目标保护距离、道路和地形避让、实体间距及首关 11 个验证点，全部通过。

静态证据为 `tmp/environment_layout/geometry_report.json`。本布局分工没有运行 Godot；运行时碰撞、导航、实际镜头密度和美术遮挡由主任务整合验证。
